# AI Teammate 运行态交互 PRD

> 文档状态：v1.0  
> 适用页面：AI Teammates → 运行态管理 → AI Teammate 详情  
> 交互参考：[task-management-demo.html](./demos/task-management-demo.html)  
> 目标读者：产品、设计、前端、后端、测试及后续实现 Agent  

## 1. 背景

AI Teammate 详情页原来主要展示“当前跟进事项”。随着 AI Teammate 承担更多持续工作，用户需要在同一个详情页里完成三类动作：

1. 查看正在执行和等待验收的工作；
2. 用自然语言给 AI Teammate 安排后续工作；
3. 查看每天自动或手动生成的工作日报；
4. 回溯该实例的历史运行与操作记录。

本 PRD 定义 AI Teammate 运行态详情页的页签结构、工作计划创建流程、工作日报快照模型和历史执行记录展示方式。

## 2. 目标

1. 用户能在同一个 AI Teammate 详情页内理解其当前工作、未来计划、日报和历史行为。
2. 工作计划可以直接由自然语言创建，并沉淀为任务管理中的常规任务。
3. 工作日报以日期快照方式展示，历史快照必须保留完整内容，而不是只保留摘要。
4. 历史执行记录以时间轴方式阅读，避免过早抽象成过多结构化字段。
5. 四个运行态页签保持一致的标题层级、空态、加载态和跳转方式。

## 3. 非目标

本期不做：

1. AI Teammate 自主修改任务优先级、负责人、权限或项目归属；
2. 工作日报的版本树、diff 对比或多版本回滚；
3. 历史执行记录的高级筛选、导出和自定义视图；
4. 把工作计划变成任务管理之外的新任务模型；
5. 让工作日报自动执行或确认任务；
6. 绕过任务管理权限校验。

## 4. 信息架构

AI Teammate 详情页保持现有头部信息区，包括头像、名称、状态、职责、模板、最近同步时间和定义入口。

头部下方新增运行态页签，顺序固定：

```text
[当前工作] [工作计划] [工作日报] [历史记录]
```

| 页签 | 主要内容 | 首屏动作 |
| --- | --- | --- |
| 当前工作 | 进行中、待验收、已完成、已归档任务 | 安排任务、查看详情 |
| 工作计划 | 自然语言创建入口和待启动计划项 | 创建计划项 |
| 工作日报 | 今日/最新日报和更早日报快照 | 更新日报 |
| 历史记录 | Agent 实例运行和操作审计时间轴 | 无 |

默认进入 `当前工作`。用户切换页签后，前端应保留本次会话内的页签选择；刷新页面后允许回到默认页签。

## 5. 全局交互规范

### 5.1 页签

- 使用 `tablist` / `tab` / `tabpanel` 或等价语义。
- 当前页签必须有明确的选中态和 `aria-selected`。
- 键盘用户可以按 `Tab` 到达页签，并使用 `Enter` / `Space` 激活。
- 页签切换不刷新整个应用，只替换详情页正文。
- 切换页签不应丢失未提交内容；工作计划输入框内容是否跨页签保留由实现记录，但不得因普通 rerender 意外清空。

### 5.2 页签标题

每个页签正文首行使用统一标题样式：

```text
[标题]                                      [数量/状态] [主操作]
```

要求：

1. 标题左对齐；
2. 数量、状态或摘要使用弱化样式；
3. 主操作右对齐；
4. 标题字号、行高、间距在四个页签中一致；
5. 宽度不足时标题优先保留，操作区可压缩或滚动，不允许标题与操作按钮重叠。

## 6. 当前工作

### 6.1 内容

`当前工作` 对应现有“当前跟进事项”能力，继续展示该 AI Teammate 被指派的非待启动任务，包括：

1. 进行中；
2. 待验收；
3. 已完成；
4. 已归档。

### 6.2 行为

1. 每个任务显示任务 ID、标题、项目、接收方、更新时间和最新进展。
2. Agent 正在运行时显示运行状态，不得伪装成静态文本。
3. 用户点击 `查看详情` 后跳转到任务管理中的任务详情。
4. 有权限用户可以继续使用现有 `安排任务`、启停、重启等操作。
5. 已归档任务放在独立分组或列表尾部，不与活跃任务混排。

## 7. 工作计划

### 7.1 页面结构

```text
工作计划                                       N 个计划项

+------------------------------------------------------------+
| 例如：请预研供应链例外决策材料……                          |
|                                                            |
| 已识别：优先级 P2 · 项目 一切皆插件 · 截止 yyyy-mm-dd      |
| [项目 ▾] [优先级 ▾] [自动提交 review] [截止日期] [创建计划项] |
+------------------------------------------------------------+

计划项 1
计划项 2
计划项 3
```

第一行是页签标题。第二行直接是自然语言对话框，不额外增加“创建计划”标题。对话框下方展示已创建的计划项。

### 7.2 自然语言输入

用户输入示例：

```text
请预研供应链例外决策材料，汇总安全库存和关键订单影响，9 月 26 日前输出一页结论。
```

输入后，系统需要实时解析并展示识别结果，至少包括：

1. 计划标题；
2. 项目；
3. 优先级；
4. 截止日期。

解析规则：

| 字段 | 默认值 | 用户显式指定时 |
| --- | --- | --- |
| 标题 | 从指令中提取短句 | 以用户输入为准 |
| 项目 | 当前任务管理工作区 | 使用指令中明确命中的项目 |
| 优先级 | `P2` | 使用用户显式指定的 `P0` / `P1` / `P2` / `P3` |
| 截止日期 | T+1 或产品默认值 | 使用用户明确说明的日期 |
| 接收方 | 当前 AI Teammate | 不可通过本入口改为其他接收方 |

解析结果必须以可读文案展示。用户修改选择器后，选择器值优先于解析预填值。

### 7.3 控制器

对话框底部提供：

| 控件 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 项目 | 单选下拉 | 当前工作区 | 限制在用户可创建任务的项目内 |
| 优先级 | 单选下拉 | `P2` | 支持 `P0`、`P1`、`P2`、`P3` |
| 自动提交 review | 复选框 | 选中 | 表示 Agent 执行完成后自动提交进入 review |
| 截止日期 | 日期选择 | T+1 | 自然语言中出现明确日期时自动覆盖 |

提交按钮文案固定为 `创建计划项`。

### 7.4 创建行为

点击 `创建计划项` 后：

1. 服务端调用 LLM / 解析服务提取任务标题、描述、项目、优先级、截止日期和自动 review 标记；
2. 在任务管理模块创建一条常规任务；
3. 接收方设置为当前 AI Teammate；
4. 任务状态为待处理 / 待启动；
5. 任务默认写入 `autoSubmitReview = true`；
6. 任务进入任务管理看板，可按普通任务继续编辑、指派、评论、验收和归档；
7. 创建成功后清空输入框，刷新工作计划列表；
8. 展示成功反馈，并保留任务 ID 或可点击入口。

如果解析失败或必填信息缺失，不得创建半成品任务。前端应提示缺失字段，让用户补齐后重试。

### 7.5 计划项列表

工作计划列表只展示已经安排且尚未开始执行的任务，即任务状态为待处理 / 待启动的任务。

每条计划项显示：

1. 任务 ID 和标题；
2. 优先级；
3. 项目；
4. 接收方；
5. 截止日期；
6. 创建时间；
7. 计划说明；
8. `查看详情` 按钮。

排序规则：

1. 先按优先级升序：`P0 → P1 → P2 → P3`；
2. 相同优先级按创建时间升序；
3. 排序必须稳定，不因刷新改变同一批数据的相对顺序。

## 8. 工作日报

### 8.1 快照模型

工作日报是某个 AI Teammate 在某个业务日期的完整快照。

```ts
type WorkReportSnapshot = {
  id: string;
  teammateId: string;
  reportDate: string;       // yyyy-mm-dd，业务日期
  generatedAt: string;      // 完整时间戳，前端可显示为 mm-dd hh:mm
  author: {
    type: "ai-teammate";
    id: string;
    name: string;
  };
  title: string;            // 默认 `${reportDate} 工作日报`
  excerpt: string;          // 用于搜索、列表和失败兜底
  contentMarkdown: string;  // 完整 Markdown 内容
  sourceRefs?: string[];    // 任务、工作流、会议等来源引用
};
```

约束：

1. 同一 `teammateId + reportDate` 只保留一份当前日报快照；
2. 手动更新今天的日报时覆盖同日期旧快照，并更新 `generatedAt`；
3. 历史日期快照不因任务后续状态变化自动重写；
4. 覆盖生成必须在审计记录中留下操作来源；
5. 前端不得根据最新任务状态重新拼装历史日报。

### 8.2 页面结构

```text
工作日报        [开始日期] 至 [结束日期] [关键词] [更新日报]

最新完整日报快照

历史记录                                              N
  |
  | 完整日报快照 N
  | 完整日报快照 N-1
```

### 8.3 筛选与刷新

第一行左侧为 `工作日报` 标题，右侧为筛选区和刷新动作。

| 控件 | 说明 |
| --- | --- |
| 日期区间 | 默认为包含今天的过去 7 天，即 `today - 6` 至 `today`；起止日期均包含边界 |
| 关键词 | 对日期、标题、摘要和 Markdown 内容做大小写不敏感的多关键词匹配；多关键词之间为 AND |
| 更新日报 | 固定生成或更新今天的日报，不更新用户正在查看的历史快照 |

交互要求：

1. 日期筛选、搜索框和 `更新日报` 按钮在同一行；
2. 搜索框宽度应明显支持关键词输入，参考 demo 中比初始方案增加 30% 的宽度；
3. 刷新动作使用文字按钮 `更新日报`，不使用纯刷新图标；
4. 生成过程中按钮显示 `更新中` 并禁用，避免重复提交；
5. 用户输入搜索词时必须保留输入框焦点和光标位置；
6. 筛选为空结果时，必须区分“没有匹配结果”和“还没有日报”。

如果用户当前筛选区间不包含今天，点击 `更新日报` 成功后，前端必须让新日报可见：可以恢复默认 7 天区间，也可以展示成功提示并跳转到今天。不得静默生成后仍停留在看不到结果的列表。

### 8.4 日报展示

每份日报快照使用同一卡片模板：

```text
yyyy-mm-dd 工作日报
撰写人：AI Teammate 名称（实例 code） · 撰写时间：mm-dd hh:mm

<Markdown 渲染内容>
```

要求：

1. 最新筛选结果中的第一份完整展示在上方；
2. 历史记录展示更早的完整日报快照；
3. 历史快照与最新快照使用相同卡片结构，仅日期和撰写时间不同；
4. 历史记录不支持点击切换、选中或展开收起；
5. 历史记录按 `reportDate` 倒序排列；
6. 日报正文必须支持 Markdown 渲染；
7. Markdown 渲染必须经过安全净化，或由服务端返回已净化 HTML；
8. 渲染失败时回退为保留换行的纯文本，不能丢失原文。

推荐 Markdown 结构包括：

```md
## 今日结论

## 执行记录

## 风险与待确认

## 明日计划
```

具体章节可由 AI 根据当日数据裁剪，但必须保留任务、事件或来源引用，不输出无依据结论。

### 8.5 生成节奏

1. 系统按配置定时生成每日工作总结，最小能力是每个业务日期生成一份；
2. 具体默认生成时间由平台配置定义，不与本交互 PRD 强绑定；
3. 用户可随时点击 `更新日报` 提前生成或刷新当天快照；
4. 定时任务失败时不得静默吞掉，应写入运行日志并允许用户手动触发。

## 9. 历史执行记录

### 9.1 定位

历史执行记录是该 AI Teammate 实例的运行和操作 audit trail，用于回答：

1. 它什么时候被创建、更新、启停；
2. 它读取了哪些已授权上下文；
3. 它启动、推进、提交或完成了哪些任务；
4. 人工用户对它做过哪些关键操作；
5. 日报生成、失败和覆盖等系统动作何时发生。

### 9.2 展示

```text
历史执行记录                                              N
  |
  | 10-26 10:12  Research Avatar 启动……
  | 10-26 09:48  Research Avatar 将 TSK-xxxx 移入进行中。
  | 10-25 17:46  Olivia 更新……
```

要求：

1. 使用时间轴顺次展示，最新记录在上方；
2. 每条记录以时间和一句叙事文本为主；
3. 避免在首版引入过多结构化字段、标签、筛选器或嵌套表格；
4. 文本中的任务 ID、用户名、工具名可以后续增强为跳转，但本期不要求；
5. 列表必须支持分页或增量加载；
6. 内容只读，不允许用户编辑或删除；
7. 空态说明该实例暂无历史执行记录。

### 9.3 写入原则

audit trail 必须追加写入：

```ts
type TeammateAuditEvent = {
  id: string;
  teammateId: string;
  occurredAt: string;
  actor: {
    type: "user" | "ai-teammate" | "system";
    id: string;
    name?: string;
  };
  narrative: string;
  refs?: {
    taskId?: string;
    workflowRunId?: string;
    reportId?: string;
  };
};
```

`narrative` 是用户可直接阅读的文本；`refs` 只作为后续扩展，不在首版 UI 中强制展示。

## 10. 权限

| 场景 | 权限要求 |
| --- | --- |
| 查看当前工作、计划、日报、历史记录 | 用户必须有权查看该 AI Teammate 实例及其归属范围 |
| 创建工作计划 | 用户必须有权在目标项目创建任务，并有权指派该 AI Teammate |
| 更新日报 | 实例 owner、平台管理员或被授权的管理角色 |
| 查看历史执行记录 | 至少与日报可见范围一致；涉及工具调用细节时可进一步收紧 |
| 查看任务详情 | 继续由任务管理模块校验 |

前端隐藏入口只作为体验优化，服务端必须做最终权限校验。

## 11. 服务端契约建议

具体 API 命名可由技术方案调整，但需要覆盖以下能力：

```http
GET  /ai-teammates/:id/tasks?status=current
GET  /ai-teammates/:id/tasks?status=planned
POST /ai-teammates/:id/work-plans
POST /ai-teammates/:id/work-plans/parse

GET  /ai-teammates/:id/work-reports?from=&to=&q=&cursor=
POST /ai-teammates/:id/work-reports/generate

GET  /ai-teammates/:id/audit-events?cursor=&limit=
```

关键返回：

1. `POST /work-plans` 返回创建后的任务对象；
2. `GET /work-reports` 返回快照数组和分页游标；
3. `POST /work-reports/generate` 返回今天的新快照或进行中任务句柄；
4. 所有列表返回必须包含服务端生成的 `updatedAt` 或等价游标。

## 12. 状态与反馈

| 状态 | 要求 |
| --- | --- |
| 加载中 | 页签正文显示轻量骨架屏或局部 loading，不阻塞页签切换 |
| 工作计划创建中 | 禁用提交按钮，避免重复创建 |
| 日报生成中 | `更新日报` 显示 `更新中` 并禁用 |
| 生成失败 | 保留原日报和用户输入，展示可重试错误 |
| 无权限 | 隐藏或禁用创建、更新动作；访问受限数据返回显式无权限态 |
| 空计划 | `当前没有待启动的工作计划。` |
| 无日报 | `还没有工作日报，可以点击右侧「更新日报」生成。` |
| 无历史快照 | `没有更早的历史快照。` |
| 无审计记录 | `暂无历史执行记录。` |

## 13. 埋点与成功指标

建议埋点：

1. 运行态页签曝光和切换；
2. 工作计划输入、解析成功 / 失败、创建成功 / 失败；
3. 通过计划项跳转任务详情；
4. 工作日报筛选、关键词搜索和手动更新；
5. 日报生成成功 / 失败 / 耗时；
6. 历史执行记录翻页深度。

成功指标：

1. 首个自然语言计划创建成功率不低于 90%；
2. 用户从计划项到任务详情的跳转可用率达到 100%；
3. 日报手动更新 P95 耗时低于 15 秒；
4. 日报生成失败率低于 1%，失败必须有可重试入口；
5. 用户在日报页无需跳转其他页面即可判断 AI Teammate 当日工作结论。

## 14. 验收标准

### 14.1 页签

1. 详情页固定展示四个运行态页签，顺序正确；
2. 默认进入 `当前工作`；
3. 四个页签标题位置和样式一致；
4. 页签切换无整页刷新。

### 14.2 工作计划

1. 输入自然语言后能看到解析预览；
2. 默认优先级为 `P2`；
3. 用户显式指定优先级或日期后，解析值正确覆盖默认值；
4. 提交后在任务管理创建常规任务，接收方为当前 AI Teammate；
5. 计划列表按优先级和创建时间排序；
6. 点击 `查看详情` 能进入对应任务详情。

### 14.3 工作日报

1. 默认日期区间为包含今天的过去 7 天；
2. 关键词可以过滤日期、摘要和正文；
3. 最新日报完整显示标题、撰写人、实例 code、撰写时间和 Markdown 内容；
4. 历史记录展示完整快照，而非摘要；
5. 历史快照不可点击切换，也没有选中态；
6. `更新日报` 固定更新今天；
7. 同一天重复更新后，该日期快照内容与 `generatedAt` 被替换；
8. 过去日期快照不因任务后续变化自动重写。

### 14.4 历史执行记录

1. 位于最后一个页签；
2. 使用时间轴叙事展示；
3. 记录按时间倒序排列；
4. 无编辑、删除或复杂筛选入口；
5. 新运行动作会追加新记录。

## 15. 开放问题

1. 工作日报是否需要按项目或工作区拆分，当前默认按 AI Teammate 实例整体生成；
2. 同一天多次手动更新时，是否需要在审计外保留生成历史，当前产品口径是同日期只保留一份当前快照；
3. 历史执行记录后续是否需要按任务、工具、错误类型筛选，当前首版不做；
4. 工作计划中的自然语言解析由服务端统一完成还是前端轻量解析后服务端复核，实现时应以服务端解析和安全校验为准。
