# 平台账号、Principal、项目角色与 AI 伙伴 GUI 端到端测试方案

> 目标版本：Principal-first Phase 4C（2026-10-17）  
> 测试类型：用户视角 GUI 功能、权限、迁移兼容、上下游集成、安全与体验回归  
> 覆盖模块：平台设置、账号与权限、项目、项目角色、成员权限、任务、工作流、会议、AI 伙伴、审计  
> 不覆盖：未来 HRM 对接、外部 Agent 协议本身的深度专项测试  
> 关联方案：`docs/platform-principal-rbac-design.md`  
> 关联专项：`docs/gui-e2e-test-plan-external-agent.md`

## 1. 测试结论定义

本方案验证的目标不是“页面能打开”，而是以下产品闭环成立：

1. 人类身份由平台账号映射到 Human Principal，不再存在企业员工产品目录。
2. AI 伙伴由 AI Principal 承载，AI 伙伴是唯一产品入口，不向用户暴露 Employee。
3. 平台角色、工作区角色和项目角色彼此独立，不通过 Owner、Persona 或模版隐式继承权限。
4. 项目成员页可以选择 Human Principal 和 AI Principal，并正确维护工作区成员角色与项目角色。
5. AI 伙伴首次派发使用 Principal Runtime，不新建 Employee 记录。
6. 历史 Employee 运行身份只作为兼容和迁移来源；迁移后继续运行不回退 Employee 主路径。
7. 任务、工作流和会议都能通过 GUI 使用 AI 伙伴，并保留可读的执行状态、历史与失败原因。
8. 归档、停用、越权、跨项目和会话失效等负向路径在 GUI 中可见且不可绕过。
9. 审计与历史可以回答“谁做的、对哪个项目、影响了谁、执行主体是谁”。
10. 桌面、窄屏、刷新、空状态和异常状态下没有布局错乱、重复数据或静默成功。

## 2. 当前产品边界

### 2.1 产品入口

| 能力                      | 唯一产品入口               | 测试口径                                       |
| ------------------------- | -------------------------- | ---------------------------------------------- |
| 平台账号、全局角色、审计  | 平台设置 → 账号与权限      | 管理员管理账号；非管理员仅能使用自己的账号能力 |
| 项目与项目角色            | 项目 → 项目详情 / 项目设置 | 平台管理员或项目负责人管理                     |
| 工作区成员角色            | 项目 → 成员权限            | 属于项目关系，不是平台全局角色                 |
| AI 伙伴、模版、运行时状态 | AI 伙伴                    | AI 伙伴是唯一 AI 产品入口                      |
| 任务与执行状态            | 任务                       | 从项目、工作台或任务模块进入                   |
| 工作流定义与实例          | 工作流                     | 项目详情可跳转实例                             |
| AI 参会代表               | 会议                       | 不展示 Employee 参会身份                       |
| Employee 历史兼容         | 无产品页                   | 只通过历史任务、运行、审计和兼容数据回查       |

### 2.2 明确不应出现

以下内容不得出现在目标产品 GUI 的主路径中：

- 平台设置中的“企业员工”页签。
- 员工目录、员工治理中心、数字员工独立创建页。
- AI 伙伴详情中的“员工档案”“员工 Runtime”等产品文案。
- 从 AI 伙伴 Owner 自动继承平台管理员、平台成员或项目角色。
- 在项目成员页修改平台账号密码、启停用状态或全局角色。
- Human Principal 与登录账号的双重人员目录。
- 同一 AI 伙伴因迁移出现两条实例记录。

### 2.3 迁移期允许存在

- Human Principal 的兼容别名为登录账号 ID。
- AI Principal 的历史别名可能为 `employeeId`，但不得成为新派发主路径。
- Employee 历史表可以保留，不新增产品入口。
- Employee 产品写接口返回 `410 gone`；该检查属于安全辅助验证，不作为 GUI 主验收路径。

### 3.5 前置数据原则

1. 账号、项目、角色和 AI 伙伴的验收步骤必须通过 GUI 完成。
2. 历史 Employee Runtime、过期 Grant、异常 Token 等无法自然产生的数据，可以用夹具或 API 准备，
   但必须在用例中标记“前置数据”，且不得计入 GUI 操作通过步骤。
3. API 只作为排障或内部状态辅助证据。不得用“接口返回成功”替代页面操作和页面结果。
4. 每个失败用例必须保留可见错误和无敏感信息的诊断证据。

## 5. 覆盖矩阵

| 领域              | GUI                     | 数据投影                      | 负向                         | 上下游                 |
| ----------------- | ----------------------- | ----------------------------- | ---------------------------- | ---------------------- |
| 登录与会话        | 登录、退出、改密、失效  | 账号状态、当前用户            | 错误密码、停用、Token 丢失   | 项目访问、任务操作     |
| 账号与全局角色    | 创建、编辑、启停用      | Human Principal 映射          | 最后管理员、非管理员         | 项目平台角色只读显示   |
| 项目成员          | 添加、编辑、移除        | Human/AI Principal 候选       | 非成员、重复添加、Owner 继承 | 任务、工作流、项目统计 |
| 项目角色          | 草稿、确认、删除        | 工作区/项目 Grant 镜像        | revision 冲突、引用阻断      | 任务改派、工作流快照   |
| AI 伙伴           | 创建、生效、暂停、归档  | AI Principal、Runtime Profile | 无项目、归档、外部运行时停用 | 任务、工作流、会议     |
| Principal Runtime | 执行状态、运行历史      | Run、Ticket、Principal ID     | Ticket 过期、上下文不匹配    | Agent 回写与 Review    |
| 历史迁移          | AI 列表、刷新、历史记录 | Employee → Principal 映射     | 重复迁移、归档 Principal     | 旧任务和旧运行继续可读 |
| 审计              | 账号审计、项目历史      | actor Principal、Grant        | 非管理员、项目角色越权       | 问题定位               |
| 页面质量          | 响应式、刷新、空状态    | 无重复、无遗漏                | Console 异常、溢出           | 全链路                 |

## 7. 端到端主验收链路

以下三条链路必须按顺序完整通过，不能拆成只验证单页。

### E2E-01 从账号到项目角色

1. 管理员初始化并创建账号。
2. 创建项目并向项目添加 Human Principal。
3. 设置工作区成员角色和项目角色。
4. 目标账号登录，能访问项目但不能修改平台账号。
5. 管理员修改其平台角色，项目工作区角色不变化。
6. 项目负责人修改其项目角色，平台角色不变化。
7. 项目历史出现正确变更记录。

### E2E-02 从 AI Companion 到任务闭环

1. Owner 创建 AI 伙伴并关联项目。
2. 项目成员页出现 AI Principal 候选。
3. 给 AI 分配项目角色。
4. 创建任务并派发给 AI。
5. 运行状态、输出和 Review 正确。
6. 暂停 AI 后不能新派发。
7. 恢复后可以再次执行。
8. 任务详情和历史全程可追溯。

### E2E-03 从历史 Employee Runtime 到 Principal-first

1. 预置带 Employee Runtime 的历史 AI。
2. 新版启动后 AI 仍可见且没有重复。
3. 打开历史任务和 Run，内容保留。
4. 新任务派发走 Principal-first。
5. Employee 产品页始终不出现。
6. 再次重启，迁移幂等，无重复 AI、无重复成员。

## 14. 已知实施注意项

以下事项不改变测试预期，但执行前需要确认：

1. AI 伙伴详情里如仍出现“绑定员工档案”等旧文案，应记录为 P1 产品术语缺陷。
2. 项目成员页应继续显示 Human Principal / AI Principal；如回退为 Employee 类型，应判失败。
3. 历史 Employee 写接口返回 `410 gone` 属于辅助安全检查，不应在 GUI 中提供入口。
4. 外部 Agent 协议失败、流式输出和命令探测的深度验证，沿用
   `docs/gui-e2e-test-plan-external-agent.md`，本方案只验证 AI 伙伴到任务/工作流/会议的产品闭环。
5. `vendor/deepseek-harness` 工作树不干净会导致 `pnpm contract` 失败；执行报告中必须与产品缺陷分开。
