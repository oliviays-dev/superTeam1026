# 工作流节点编码与缩进设计

## 背景

工作流详情当前把「多入边」节点误判为分支节点并加缩进，导致并行汇合节点
（例如「代码测试」）出现与嵌套流程相同的左缩进。缩进应只表达父子嵌套关系，
不表达分支/汇合关系。

本设计只调整前端展示模型，不修改工作流存储、拓扑语义或节点动作。

## 基本概念

- **主序号**：顶层流程中的顺序阶段号，从 1 开始。
- **并行分支号**：同一阶段内并列执行的泳道号，从 1 开始。
- **子流程内序号**：进入子流程后，在子流程定义内重新计算的阶段号。
- **汇合节点**：排除循环回边后，前向入度大于 1 的节点。
- **节点身份**：节点真实身份始终是 `node.id`；编码只用于展示和沟通。

## 编码语法

```text
<主序号>[a|b… 或 -<并行分支号>](.<子流程内序号>[a|b… 或 -<并行分支号>])*
```

- `-` 表示同一层的并行分支。
- `a/b/c…` 表示同一层的 N 选 1 互斥分支。
- `.` 表示进入子流程后的父子层级。
- 子流程内部编号保留完整父路径，不重置为 `1`。

示例：

| 编码 | 含义 |
|---|---|
| `1`、`2` | 顶层顺序节点 |
| `3-1`、`3-2` | 第 3 阶段的并行分支 1、2 |
| `2a`、`2b` | 第 2 阶段的 N 选 1 互斥分支 |
| `4` | 并行汇合节点（回到主干，不缩进） |
| `5.1`、`5.2` | 子流程父节点 `5` 内部的两个节点 |
| `3-1.1` | 并行分支 `3-1` 内子流程的第 1 个节点 |
| `3-1.1-2` | 该子流程节点内部的第 2 条并行分支 |

### 当前「软件开发交付 v2」示例

```text
1   产品方案设计
2   产品 PRD 评审
3-1 开发          ┐ 并行
3-2 测试文档设计   ┘
4   代码测试       ← 汇合
5   发布确认
```

## 并行流程 vs N 选 1 分叉

两者都是同一个节点分出多条边，但语义不同：

- **并行流程**：多条边同时生效，所有分支都会执行。
  - 容器：虚线框，标题「并行流程」。
  - 编码：`3-1`、`3-2`。
- **N 选 1 分叉**：根据条件 / 结果只走其中一条分支。
  - 容器：实线框，标题「分支流程 · N 选 1」。
  - 编码：`2a`、`2b`。
  - 节点上展示分支条件（condition / label / 默认分支）。

判定口径：

- 分叉源是 `decision` 节点；
- 或分叉边包含 `condition`、`default: true`；
- 或分叉边的 `result` 不同（例如通过 / 退回）。

以上任一条件成立即按 N 选 1 分叉展示，否则按并行流程展示。

## 缩进规则

- 只有 `.` 层级增加缩进，每级 16px。
- 并行分支 `-` 不缩进，放在「并行流程」容器内按泳道排列。
- 汇合节点不缩进，回到主干层。
- 循环/返工回边不缩进，用回边和循环标注表达。
- 同一节点重跑不改变编码，只显示「第 N 轮」。

## 视觉标识

- **类型标签**：执行 / 审批 / 决策 / 服务，沿用现有样式。
- **汇合标签**：在前向入度大于 1 的节点上显示「汇合」，使用中性灰。
- **子流程标签**：在 `type = subworkflow` 的父节点上显示「子流程」，使用中性灰。
- 并行分支节点不再额外显示「并行」标签；容器标题 + `-` 编码已足够。
- 节点详情列表、流程概览、子流程卡片共用同一份编码。

## 汇合判定

1. 先识别循环回边（DFS 指向当前访问栈的边），从拓扑计算中排除。
2. 统计剩余前向边的入度。
3. 前向入度 > 1 的节点标记为 `join`，不缩进，并显示「汇合」。

## 展示模型

前端生成一份只读的 `WorkflowNodePresentation`：

```ts
interface WorkflowNodePresentation {
  nodeId: string;
  code: string;          // 如 3-1.1
  depth: number;         // 仅子流程增加
  parallel: boolean;     // 是否位于并行泳道
  join: boolean;         // 前向入度 > 1
  subflow: boolean;      // 是否为子流程父节点
}
```

- 顶层按拓扑分层生成：单节点阶段用主序号；多节点阶段用 `主序号-分支号`。
- 子流程内部递归生成：传入父节点编码作为前缀，`depth + 1`。
- 节点详情列表与流程概览使用同一份模型，避免两处编码不一致。

## 边界情况

- **循环/返工**：回边不参与入度和分层；节点编码稳定，轮次单独展示。
- **不可达节点**：追加到主序列末尾，避免丢失。
- **并行阶段内的子流程**：先取并行编码，再在其后追加 `.子序号`。
- **子流程内并行**：在子流程段后继续使用 `-`，如 `5.2-1`。
- **模板版本变化**：编码是展示值，可能随模板结构变化；审计仍以 `node.id` 为准。

## 非目标

- 不修改工作流定义格式、实例存储或节点执行语义。
- 不新增后端字段。
- 不把并行分支改造成子流程。
