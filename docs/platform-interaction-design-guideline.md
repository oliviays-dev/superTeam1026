# 平台交互与视觉设计规范

> 文档状态：v1.0（2026-10-17）  
> 适用范围：`dsh-pluginmax` 下全部 `dsh-collab-*` 前端模块  
> 依据：**已落地工程代码**，不包含演示稿口径  
> 目标读者：产品、设计、前端、测试，以及后续实现 Agent

## 0. 本文的定位

平台现有前端模块各自实现了页面、表单、详情和弹窗，但字号、边框、按钮高度、层级、反馈时长等细节并不完全一致，导致模块之间"像拼起来的"。本文做两件事：

1. **固化已经形成的范式**：把工程里反复出现、验证有效的做法写成规则；
2. **收敛已经出现的偏差**：给出统一取值与整改清单，避免继续扩散。

规范分两类条目：

- **必须（MUST）**：新代码必须遵守，存量代码按第 11 节逐步整改；
- **建议（SHOULD）**：在无明显理由时采用，允许局部例外并在评审中说明。

## 1. 设计原则

### 1.1 一致性优先于局部最优

同一种信息在不同模块必须用同一种组件表达。列表项、状态标签、空态、弹窗、按钮高度不允许按模块自定义一套。

同一个动作在全平台必须使用同一种控件与同一个图标：关注统一用星形图标按钮，刷新统一用刷新图标，打开实体详情统一用「详情」文字按钮。不得出现「项目详情用文字按钮、工作台用星形按钮」这类同义不同形的情况。

一致性分三层，缺一层都会重新走向分裂：

| 层级 | 要求 | 目的 |
| --- | --- | --- |
| 措辞一致 | 同一概念、同一动作只用一个词 | 降低理解成本 |
| 结构一致 | 同一类页面使用同一套布局骨架（页头 / 列表-详情 / 详情头 / 区块头） | 降低学习成本 |
| 实现一致 | 同一结构只保留一个组件实现，通过 props 表达差异 | 降低研发与维护成本，提高复用率 |

同一结构在代码中出现第 3 次时必须抽成共享组件或共享渲染函数。

### 1.2 信息密度优先

这是工作型后台，不是营销站。优先保证一屏内可比较、可扫描：

- 正文 13px、行高 1.5～1.6；
- 行高 32～44px，卡片内边距 10～12px；
- 不使用大面积留白、超大标题、装饰性插画。

### 1.3 状态必须可见

任何异步数据都要有明确状态：加载中、空、失败、只读、处理中、已完成。禁止出现"点完没反应"。

### 1.4 渐进确认

影响面小的编辑直接保存；影响面大（跨对象、批量、不可回滚）的编辑走"草稿 → 差异 → 确认"。判断标准见 6.2。

### 1.5 权限边界清晰

平台级信息、工作区级信息、项目级信息分层展示。低层级页面不得修改高层级数据，且要用只读样式明确表达，而不是伪造成可编辑控件。

### 1.6 永远可以返回

进入详情必须能回到来源列表或来源模块，并保留来源上下文（筛选、搜索、选中项、来源页签）。

## 2. 视觉基线

### 2.1 颜色令牌（MUST）

所有颜色必须使用宿主提供的 `--dsw-alias-*` 令牌。令牌缺失时才能写 fallback，且全平台只允许一套 fallback 值。

| 令牌 | 用途 | 禁止用于 |
| --- | --- | --- |
| `--dsw-alias-bg-base` | 页面底色、输入框底色 | 卡片背景 |
| `--dsw-alias-bg-layer-1` | 卡片、面板、弹窗背景 | 页面底色 |
| `--dsw-alias-bg-layer-2` | 次级块、hover 背景、代码块 | 主内容背景 |
| `--dsw-alias-bg-layer-3` | 选中页签、未激活 pill、头像底 | 大面积背景 |
| `--dsw-alias-border-l2` | 结构分隔线、看板列、面板头 | 输入框边框 |
| `--dsw-alias-border-l3` | 控件边框、卡片边框、弹窗边框 | 强调态 |
| `--dsw-alias-border-l4` | hover / 强调边框 | 常规边框 |
| `--dsw-alias-label-primary` | 主文本、标题、数值 | 说明文字 |
| `--dsw-alias-label-secondary` | 说明、meta、占位、未选中页签 | 主标题 |
| `--dsw-alias-label-tertiary` | 时间戳、编号、极弱提示 | 正文 |
| `--dsw-alias-label-primary-foreground` | 主按钮文字 | 普通文本 |
| `--dsw-alias-button-primary-fill` | 主按钮底色 | 装饰背景 |
| `--dsw-alias-accent-primary` | 链接、选中态、强调数字、进度 | 成功/失败语义 |
| `--dsw-alias-accent-fill` | 强调填充（少用） | 文本颜色 |
| `--dsw-alias-state-success-primary` | 成功、健康、已完成 | 主按钮 |
| `--dsw-alias-state-warning-primary` | 关注、等待、待验收 | 错误 |
| `--dsw-alias-state-error-primary` | 风险、阻塞、失败、危险操作 | 成功 |
| `--dsw-alias-button-floating-fill` | 悬浮把手、浮层按钮 | 普通按钮 |
| `--dsw-alias-button-floating-hover` | 悬浮把手 hover | 普通按钮 |
| `--dsw-alias-brand-primary` | 品牌标识专用 | 业务状态 |

**禁止**：在业务组件中写死 `#fff`、`#000`、`rgba(...)` 作为文本或背景色；需要透明度时用 `color-mix(in srgb, token X%, transparent)`。

**例外**：头像插画色板、AI 头像渐变环、品牌 logo 可以使用固定色值。

### 2.2 语义色板

平台当前实际使用的主色与状态色，统一收敛为以下五种。**同一个语义只允许一个 fallback**：

| 语义 | 令牌 | 唯一 fallback | 典型用途 |
| --- | --- | --- | --- |
| 强调 / 进行中 | `--dsw-alias-accent-primary` | `#4f8ef7` | 选中态、进度、链接、进行中 |
| 成功 / 健康 | `--dsw-alias-state-success-primary` | `#34d47e` | 已完成、健康、保存成功 |
| 关注 / 等待 | `--dsw-alias-state-warning-primary` | `#e2a737` | 待验收、等待、关注 |
| 风险 / 失败 | `--dsw-alias-state-error-primary` | `#e5534b` | 阻塞、风险、错误、删除 |
| AI / Agent | 建议新增 `--dsw-alias-agent-primary` | `#8b7bf7` | AI 相关标签、实例标识 |

**浅色底规则**：状态标签不要使用不透明深色底，统一用 12%～16% 透明度：

```css
background: color-mix(in srgb, var(--dsw-alias-state-warning-primary, #e2a737) 14%, transparent);
color: var(--dsw-alias-state-warning-primary, #e2a737);
```

> 现状问题：`dsh-collab-workflow` 的 `.pmwf-pill.running/blocked/waiting` 写死了深色底（`#16301f`、`#3d2222`、`#372c14`），在浅色主题下会失效，需按本节整改。

### 2.3 字号阶梯（MUST）

工程现状出现了 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 七个相邻字号，视觉上无法区分，却造成了模块差异。统一为 **七级**（0.5px 全部归并）：

| 级别 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面标题 | 19px / 1.3 | 700 | 每个全局功能页的 `h1` |
| 详情标题 | 15～17px / 1.35 | 650 | 详情面板标题、弹窗标题、区块大标题 |
| 卡片标题 | 14px / 1.3 | 650 | 工作台模块标题、紧凑卡片标题 |
| 正文 | 13px / 1.6 | 400 | 列表正文、段落、表单值 |
| 次要正文 | 12px / 1.5 | 400 | 按钮、表单、说明、meta |
| 辅助 | 11px / 1.5 | 400 | 标签、计数、提示、时间 |
| 微型 | 10px / 1.4 | 500～700 | 编号、徽标、极小标签 |

存量迁移映射（机械替换，不需要重新设计）：

| 现有值 | 迁移到 |
| --- | --- |
| 9px | 10px |
| 10.5px | 11px |
| 11.5px | 12px |
| 12.5px | 13px |
| 13.5px | 13px 或 15px（看层级） |
| 18px（页面标题） | 19px |

> 页面标题在 `task` / `project` / `teammate` / `workflow` 已是 19px，`shell` 占位页是 18px，需对齐到 19px。

### 2.4 间距体系（MUST）

以 **4px** 为基准，允许 2px 作为图标与文字的贴合间距。

| 场景 | 取值 |
| --- | --- |
| 图标与文字 | 4～6px |
| 按钮组、标签组 | 6～8px |
| 卡片内元素 | 8～10px |
| 页面区块之间 | 10～12px |
| 页面大区块之间 | 14～16px |
| 页面内边距 | `18px 20px 28px`（由 shell `.pmx-page` 统一提供） |
| 卡片内边距 | `10px 12px`（紧凑卡片 `9px 10px`） |
| 面板内边距 | `12px 14px` |
| 弹窗内边距 | `16px` |

禁止出现 11px、13px、15px 这类非体系间距。

### 2.5 圆角

| 元素 | 圆角 |
| --- | --- |
| 标签 chip、徽标 | 4px |
| 按钮、输入框、下拉 | 6px |
| 列表项、卡片、行容器 | 7px |
| 面板、看板列、弹窗 | 8px |
| 阻塞式登录卡片 | 12px |
| 状态 pill | 999px |

### 2.6 边框

| 场景 | 规格 |
| --- | --- |
| 控件、卡片、列表项 | `0.5px solid var(--dsw-alias-border-l3)` |
| 结构分隔线（侧栏、详情栏、面板头） | `1px solid var(--dsw-alias-border-l2)` |
| hover / 强调 | `1px solid var(--dsw-alias-border-l4)` 或 `color-mix(accent 45%, transparent)` |
| 空态 / 只读区 | `0.5px dashed var(--dsw-alias-border-l3)` |

> 现状问题：`task` / `workflow` / `workbench` 大量使用 1px 卡片边框，`project` / `teammate` 使用 0.5px。统一按本表，存量逐步替换。

### 2.7 阴影

| 层级 | 规格 | 用途 |
| --- | --- | --- |
| 浮层 1 | `0 12px 28px rgba(0,0,0,.18)` | 下拉菜单、账户菜单、提示气泡 |
| 浮层 2 | `0 14px 34px rgba(0,0,0,.28)` | 弹窗、toast、拖拽中的卡片 |
| 浮层 3 | `0 18px 48px rgba(0,0,0,.35)` | 阻塞式弹窗、拖动预览 |

阴影只用于"离开页面平面"的元素。卡片静态不使用阴影。

### 2.8 图标

| 场景 | 尺寸 |
| --- | --- |
| 行内图标（按钮内、输入框内） | 13～14px |
| 导航图标 | 15px |
| 独立图标按钮 | 28×28 或 32×32 |
| 空态 / 大状态图标 | 20～24px |

统一使用线性图标：`viewBox="0 0 24 24"`、`fill="none"`、`stroke="currentColor"`、`stroke-width="2"`、圆角端点。

### 2.9 层级（z-index，MUST）

现状出现 1 / 3 / 4 / 20 / 24 / 30 / 35 / 60 / 70 / 80 / 1000 / 1200 十二种取值。统一为以下阶梯：

| 层级 | 值 | 用途 |
| --- | --- | --- |
| 基座 | 0 | 应用壳层 |
| 卡内浮层 | 1～4 | 拖拽卡片、卡内遮罩（必须位于隔离的层叠上下文内） |
| 下拉 / 气泡 | 20 | select menu、mention、tooltip |
| 侧栏 / 吸附头 | 30 | 沟通侧栏、详情轨道、sticky 表头 |
| 弹窗遮罩 | 60 | 所有 modal |
| Toast | 70 | 全局轻提示 |
| 阻塞层 | 1000～1200 | 登录门禁、全屏加载 |

新代码禁止出现 24、35、80 等中间值。

## 3. 布局规范

### 3.1 应用壳层

```text
┌───────────┬──────────────────────────────┬──────────────┐
│ 左侧导航   │ 主内容区                      │ 详情轨道       │
│ 264 / 72  │ minmax(0, 1fr)               │ min(360,32vw)│
└───────────┴──────────────────────────────┴──────────────┘
```

- 左侧导航展开 264px，收起 72px；
- 右侧详情轨道仅在存在上下文详情时出现，宽度 `min(360px, 32vw)`；
- 沟通侧栏为可拖拽宽度，默认独立于详情轨道；
- 壳层负责页面内边距、滚动容器、主题和登录门禁，模块不重复实现。

### 3.2 页面容器（MUST）

shell 会在全局路由外包一层 `.pmx-page`，提供：

```css
padding: 18px 20px 28px;
min-height: 100%;
display: flex;
flex-direction: column;
```

因此模块根节点**不得**再叠加页面级 padding，只负责自身内容布局。

### 3.3 页头（MUST）

所有全局功能页统一结构：

```text
标题（19px / 700）                          [次要操作] [主操作]
副标题（12px / secondary，可选）
```

- 页头与内容间距 14px；
- 操作区右侧对齐，按钮间距 8px；
- 主操作最多 1 个；
- 页头不得出现装饰性图标或大段说明。
- 页头副标题只承载必要的范围或上下文，不写功能清单、功能说明或产品文案；界面本身能表达的，不再额外加静态说明段。

> 例外：工作台以「我的工作台 / 管理驾驶舱」分段控件作为页头，不渲染 `h1`；模块卡片标题使用 14px / 650。

项目详情头部固定两行元信息：

1. 项目编号 · 负责人 · 起止日期；
2. 工作区 ID · 工作区路径，均可复制。

详情头部不展示功能描述性文案；页面区块内也不额外增加「这个功能怎么用」的静态说明段。

```css
.xxx-head{display:flex;align-items:flex-start;justify-content:space-between;gap:16px;flex-wrap:wrap;margin-bottom:14px}
.xxx-head h1{margin:0;font-size:19px;line-height:1.3}
.xxx-sub{margin-top:4px;color:var(--dsw-alias-label-secondary);font-size:12px}
.xxx-head-actions{display:flex;align-items:center;gap:8px;flex-wrap:wrap}
```

### 3.4 主从结构（列表 + 详情）

平台存在三种合法变体，按数据量选择：

| 变体 | 结构 | 适用 |
| --- | --- | --- |
| A. 目录 + 详情 | 左列 `minmax(230px,290px)`，右列自适应 | 项目、AI 伙伴、会议目录、任务模版 |
| B. 指标摘要 + 全宽列表 | 顶部关键指标汇总、筛选 / 搜索器，下方全宽实例列表；实例详情同页下钻 | 工作流实例列表 |
| C. 看板 + 抽屉 | 列看板占满，详情用右侧抽屉或独立详情区 | 任务管理 |

规则：

- 采用列表 + 详情的主从结构时默认选中第一项，不出现"空白详情"；工作流列表页按需下钻，并保持选中项可恢复；
- 选中项：边框 accent 55% + 背景 accent 12%；
- 列表项统一两行结构：主名称 12px/650，副信息 11px/secondary；
- 切换选中项时，详情回到默认页签；
- 列表与详情独立 loading，详情加载不阻塞列表。

### 3.5 看板 / 画布

- 任务看板：列等宽 `grid-auto-columns: minmax(0,1fr)`，列间距 12px；
- 工作台画布：6 等分栅格，间距 14px，模块宽度 1～6 列；
- 卡片拖拽：标题行作为拖拽把手（`cursor: grab`），拖拽中 `opacity: .48`，落点区 accent 边框 + 7% 背景；
- 模块高度可调，范围 190～900px。

### 3.6 响应式断点

| 断点 | 行为 |
| --- | --- |
| `max-width: 900px` | 两栏 → 单栏；指标 3 列 → 1 列；表单 2 列 → 1 列；行表格 → 单列堆叠 |
| `max-width: 640px` | 角色编辑行、复杂多列行 → 单列 |

工作台在 900px 以下固定为 2 列栅格，模块占满 2 列。

## 4. 组件规范

### 4.1 按钮

| 类型 | 高度 | 内边距 | 字号 | 样式 |
| --- | --- | --- | --- | --- |
| 主按钮 `.primary` | 32px | 0 12px | 12px / 600 | 填充 `button-primary-fill`，文字 `label-primary-foreground` |
| 次按钮 `.secondary` | 32px | 0 12px | 12px / 500 | 透明底，0.5px `border-l3` |
| 危险按钮 `.danger` | 32px | 0 12px | 12px / 500 | 透明底，45% error 边框，error 文字 |
| 小按钮 `.small` | 28px | 0 10px | 12px | 沿用上述颜色 |
| 图标按钮 | 28×28 或 32×32 | 0 | — | 0.5px `border-l3`，圆角 6px |

```css
.btn{height:32px;display:inline-flex;align-items:center;justify-content:center;gap:6px;border:0;border-radius:6px;padding:0 12px;background:var(--dsw-alias-button-primary-fill);color:var(--dsw-alias-label-primary-foreground);font:inherit;font-size:12px;font-weight:600;cursor:pointer;white-space:nowrap}
.btn.secondary{background:transparent;border:0.5px solid var(--dsw-alias-border-l3);color:var(--dsw-alias-label-primary);font-weight:500}
.btn.small{height:28px;padding:0 10px;font-size:12px}
.btn:disabled{opacity:.5;cursor:not-allowed}
```

文案规则：动词开头、2～4 个字（新建项目、保存变更、确认生效、移除成员）。禁止"确定/取消"式的无信息按钮，除非是确认对话。

### 4.2 页签

平台有三种页签，必须按场景选择，不得混用：

| 类型 | 规格 | 场景 |
| --- | --- | --- |

### 4.15 语义控件对照（MUST）

同一语义只允许一种控件表达。下表为强制约定：

| 语义 | 控件 | 状态表达 | 禁止 |

### 4.16 组件复用契约（MUST）

页面只能由下列基础组件组合而成。组件通过 props 表达差异，不允许按模块复制一套新结构。

| 组件 | 统一结构 | 关键参数 | 使用位置 | 禁止 |
| --- | --- | --- | --- | --- |
| PageHeader | 标题 + 副标题 + 右侧操作区 | `title` `sub` `actions` | 所有全局功能页 | 页面自写 `h1` 布局 |
| SplitLayout | 左目录 230–290px + 右详情自适应 | `directory` `detail` | 项目、AI 伙伴、项目模版 | 自写两栏 grid |
| ListButton | 双行文案 + 尾部状态 | `active` `title` `subtitle` `trailing` | 所有目录列表 | 自写 `list-item`；目录首字方块 / 头像 |
| DetailHeader | 标题 + pill + meta + 描述 + 操作 | `title` `pills` `meta` `desc` `actions` | 所有详情页 | 自写 `detail-head` |
| SectionHeader | 区块标题 + 数量 / 操作 | `title` `count` `actions` `level` | 面板、卡片、区块 | 自写 `section-head` |
| DataTable / Row | 表格容器 + 行 + 操作列 | `columns` `rows` | 成员、角色、账号、日报 | 自写 `table` / `row` |
| FormModal | 遮罩 + 标准/宽弹窗 + 头 + 表单 + 底部操作 | `title` `fields` `footer` | 新建、编辑、设置 | 各模块自定义弹窗结构 |
| Drawer | 右侧抽屉 + 头 + 内容 + 底部操作 | `title` `body` `actions` | 任务详情、辅助详情 | 用全屏跳转替代 |
| Toolbar | 左侧筛选 + 弹性间隔 + 右侧操作 | `filters` `actions` | 列表页、看板页 | 筛选散落在页面各处 |
| StatusPill | 语义色 + 固定内边距 | `tone` | 所有状态 | 时间 / 数量套用 |
| EmptyState | 虚线容器 + 统一句式 | `text` | 所有空态 | 只写「暂无数据」 |
| Toast | 底部居中 + 自动消失 | `message` `type` | 全局操作反馈 | `alert()` |

实现约定：

- 差异只能通过 `variant` / `tone` / `size` / `level` 等参数表达，不得新增平行组件。
- 同一组件的结构、间距、字号、圆角只在一个地方定义。
- 业务页面只负责拼装数据与传参，不负责重新定义布局。
- 目录列表保持纯文本双行结构，不再为每个对象渲染首字方块或头像；对象区分交给名称、副标题与状态。

> 当前 demo 已抽出 `pageHead` / `splitLayout` / `listButton` / `detailHead` / `sectionHead` / `emptyState` / `followButton` 等共享渲染函数，可作为工程侧组件拆分的参照。

### 4.17 工作流概览图（MUST）

工作流详情必须在标题之后先给出一张横向流程概览图，用户无需滚动即可判断整体结构与当前阶段。

| 元素 | 规则 |
| --- | --- |
| 节点形状 / 颜色 | 颜色只区分审批 vs 执行：审批=圆角矩形 + agent 色；执行=尖角矩形 + accent 色。决策=中性色平行四边形；子流程=中性色虚线容器 |
| 节点状态 | 已完成=success，执行中=accent，阻塞=error，等待中 / 已跳过=neutral；节点卡状态标、状态描边与详情 pill 共用同一映射 |
| 节点内容 | 第一行为自动编号与节点名称；第二行为负责人和 `DDL mm-dd`，已完成节点该位置改显实际完成时间 `MM-DD HH:mm`；底部左侧为 `交付：X/N`，右侧为状态标签；不在卡内重复类型文字 |
| 交付物入口 | `交付：X/N` 中的数字可点击，在节点附近展开交付物气泡；气泡按「要求：结果」列出，结果可为文件名或 `NA`，再次点击、点击外部或 Esc 收起 |
| 节点卡片 | 类型由形状 + 图例表达；第一次点击选中并聚焦详情，再次点击同一节点取消选中并恢复全部节点详情；选中态在详情标题栏提供「展开全部节点」，不使用弹窗关闭图标 |
| 当前阶段 | 不加右上角状态点；执行中使用 accent 外描边，阻塞不额外加 error 外框，由红色状态标签表达 |
| 分支 | 独立分支容器，标题 + 并行节点；顺序节点编号为 `1 / 2 / 3`，并行节点按 `2-1 / 2-2` 编号；不再显示法务 / 质量等泳道标签 |
| 循环 | 概览下方 dashed 回退说明：`↺ 失败 → 回退节点（最多 N 次）` |
| 嵌套 / 子流程 | 概览中只显示一个子流程节点；点击后，在节点详情内展示子流程的横向详细图 |
| 点击节点 | 在概览下方同页展开节点详情，不跳转页面；未选中节点时按流程顺序铺开全部节点详情，概览与详情使用同一编号 |
| 展开概览 | 复杂流程提供「展开流程图」，在宽弹窗中展示完整横向流程 |
| 实例列表 | 列表页先展示关键指标、范围 / 搜索 / 项目 / 状态筛选，再展示全宽实例列表；选中实例后同页下钻详情，「返回工作流列表」恢复列表并保留筛选与选中上下文 |

节点详情必须包含：节点编号、负责人、实际执行人、SLA/DDL、更新时间、交付物要求清单、业务详情（审批 / 表单 / 交付物 / 任务 / 会议）、嵌套子流程、节点操作。子流程节点沿用父节点前缀，例如 `2-1 / 2-2`。

节点详情标题顺序为「编号 → 节点名称 → 类型标签」，状态 pill 固定靠右；卡片内“节点交付物”“业务详情”“子流程”等分区标题降一级，使用 12px / 600 / secondary 文字，不与节点名称争夺视觉层级。

节点详情中的类型标签统一使用中性色，不以审批紫 / 执行蓝区分类型；类型识别仍由流程概览卡的形状与左侧色条承担。

交付物区按“要求项 → 实际值”展示：已提交时显示文件名，未提交时显示 `NA`；结果值与要求名称相同时省略重复副行；节点没有交付物要求时显示“无交付物要求”。业务附件需排除当前节点已作为交付物展示的同名文件。SLA 辅助说明为空时不渲染占位破折号。

**节点业务信息露出规则**

| 区块 | 露出条件 | 展示内容 | 不展示 |
| --- | --- | --- | --- |
| 审批信息 | 当前节点 `business.kind = approval` | 审批人、当前结论、审批意见 | 不聚合整条流程的其他审批记录 |
| 关联会议 | 当前节点存在显式 `meetingIds`，兼容旧字段 `business.kind = meeting` | 会议编号、标题、时间、状态与“打开”入口 | 不按项目、时间或参与人自动推断关联会议 |
| 业务附件 | 当前节点存在显式 `attachments`，兼容旧字段 `business.kind = deliverable` | 文件名、上传人、上传时间、大小与下载入口 | 不与节点交付物要求或实例级交付物混合 |
| 子流程 | 当前节点 `children` 非空 | 子流程横向概览与子节点详情 | 没有子节点时不渲染空区块 |

业务信息按「审批信息 → 关联会议 → 业务附件 → 子流程」顺序展示；没有数据的区块不占位。示例节点“停机窗口锁定”同时展示关联会议与业务附件。

输出物动作按类型区分：文档 / 文件 →「下载」；链接 / 数据 →「复制」。

- 沟通侧栏同时支持 AI 对话和会议：AI 线程在标题行展示 owner 和带聊天图标的「AI 对话」标识，不渲染单页签行与设置快捷入口；会议线程固定为「对话 / 概要 / 纪要 / 设置」，对话作为第一个页签；
- “概要”页签上半部分展示会议状态、说明、项目、时间与操作，下半部分展示参会人员列表和添加 / 移除入口；
- “设置”页签内联展示会议主题、时间和概要，保存后直接刷新侧栏；右上角齿轮作为进入设置页签的快捷入口，不再打开独立弹窗；
- 全局导航“沟通”进入中间沟通工作区：左侧为完整沟通会话列表，右侧为当前 AI 对话或会议工作区；
- 会议页头提供「仅看已加入 / 平台全量」数据范围切换，列表、计数和右侧栏切换器共享同一范围；切换到未加入会议时保留历史只读；
- 页面右上角操作区固定提供沟通图标，用于在其他模块或中间沟通页打开右侧沟通侧栏；打开时图标显示选中态；
- 中间沟通工作区与右侧栏独立维护当前会话、页签和输入草稿，可以同时查看或操作 AI 对话与会议；数据范围偏好共享；
- 沟通标题右侧提供无边框放大镜切换入口；展开后支持按名称搜索跨项目、跨类型的 AI 对话与会议，列表项展示头像、名称、项目或归属及状态；
- 切换会议时侧栏保持打开，更新会议标题与页签内容，并回到「对话」页签；
- 切换器优先展示进行中和最近会话，可搜索并直接切换，不额外放置返回沟通中心的入口；
- 中间沟通工作区大屏使用「会话列表 + 主工作区 + 上下文」三列；主工作区承载 AI 对话，或会议的对话、纪要、设置，不重复“概要”页签；上下文列按类型展示 AI 信息或会议概要、统计和参会人员；
- 打开右侧并行沟通侧栏时，中间页的上下文列自动收起，保留会话列表与主工作区，避免第四列挤压；
- 设置表单在主工作区使用两列布局，主题与时间并排、概要整行；纪要空态占满主工作区；
- 沟通列表左侧使用「类型下拉 + 搜索框 + 搜索按钮」单行工具栏，类型为全部会话 / AI 对话 / 会议，并提供完整列表和发起会议；
- 历史消息按时间正序展示，自己的消息右对齐，他人与 AI 消息左对齐；消息包含发送者、时间和正文；
- `@姓名` 使用 accent 文本与浅色底高亮，对方必须是当前会议参与人；
- 输入框仅在会议进行中可用；已结束会议显示只读历史，未开始会议提示暂不可发送；
- 点击输入区 `@` 按钮或输入 `@` 打开参与人选择器，选择后插入结构化 mention token；
- 发送后消息立即进入历史并滚动到底部；被 @ 的 AI 参与人在 demo 中生成一条回执消息。

### 4.19 项目阶段性产出物

- 项目详情新增「产出物」页签，不替换任务、工作流、项目日报和历史记录；
- 产出物按「项目阶段 → 产出时间」组织：阶段作为一级分组，组内按产出时间倒序形成时间轴；
- 筛选区在内容顶部单行排列，包含阶段、主题、开始日期、结束日期、关键词与清除入口；筛选条件在切换详情时保留；
- 每条产出物展示文档图标、文件名、主题、项目阶段、产出时间、产出者与来源；
- 产出者为人类或 AI 伙伴时均展示头像与名称，AI 伙伴追加使用 agent 色的「AI」标签；
- 来源使用带类型图标的追溯按钮：任务卡、工作流、会议分别显示来源类型与编号；人工直接上传只显示「人工上传」，不生成虚假来源；
- 点击文件名打开只读「产出物详情」，展示格式、项目、阶段、主题、产出时间、产出者、来源记录和摘要；
- 点击任务卡 / 工作流 / 会议来源进入对应原记录：任务打开任务详情，工作流打开实例详情，会议在当前页面右侧并行打开；
- 项目产出物与工作流节点交付物是两个层级：节点交付物负责流程门禁，项目产出物负责项目阶段资产；同一文件只能通过来源引用建立关系，不复制成两份事实；
- 产出物页签无数据时使用“当前项目还没有阶段性产出物。”，筛选无结果时使用“没有匹配的阶段性产出物。”。

## 5. 统一清单（术语与数据口径）

### 5.1 身份四层模型（MUST）

平台的身份相关概念分为四层，界面上必须使用对应术语，不得统称「用户」：

| 术语 | 定义 | 使用位置 | 禁止 |
| --- | --- | --- | --- |
| 登录账号 | 认证凭据：登录 ID / 邮箱、密码、启停用 | 身份与权限 →「登录账号」；设置 →「登录账号」 | 与「员工」混用 |
| 员工 | 组织中的员工档案，分真人员工与数字员工 | 身份与权限 →「员工目录」 | 泛指登录账号 |
| 真人员工 | 员工目录中由真人账号派生的档案 | 员工目录类型、成员类型 | 写成 Human Employee |
| 数字员工 | 员工目录中由 AI 伙伴绑定的档案 | 员工目录类型 | 写成数字分身、分身 |
| 项目成员 | 某个员工加入项目后的席位 | 项目 →「成员权限」「添加成员」 | 与员工目录混用 |
| AI 伙伴 | 面向用户的 AI 协作实例与入口 | 导航、页面、任务负责人、成员类型 | 写成 AI Teammate、分身 |

补充规则：

- 客户界面不出现「用户」；需要泛指时，按场景写「登录账号」「员工」「成员」。
- 「实例」只用于技术语境：流程实例、AI 伙伴实例定义；用户可见计数写「N 位 AI 伙伴」。
- 「AI Teammate」「数字分身」「分身」仅允许作为历史数据或底层字段名，不得进入界面文案。

### 5.2 三层角色模型

| 层级 | 名称 | 取值 | 维护位置 | 在项目内的表现 |
| --- | --- | --- | --- | --- |
| 平台 | 平台角色 | 平台管理员 / 平台负责人 / 平台成员 / 平台访客 | 身份与权限 | 只读展示，不可编辑 |
| 工作区 | 工作区角色 | 负责人 / 成员 / 访客 | 项目成员管理 | 可编辑（有管理权限时） |
| 项目 | 项目角色 | 项目负责人 / 开发实施 / 评审 / 审批… | 项目设置 | 可多选，用于任务指派与工作流流转 |

三层角色名称不得互相替代。项目内修改成员时，平台角色只读，工作区角色与项目角色可编辑。

项目级定义统一收口到「项目设置」，项目设置包含三个页签：

| 页签 | 归属 | 说明 |
| --- | --- | --- |
| 基础信息 | 项目级定义 | 负责人、状态、健康度、进度、日期、说明 |
| 项目角色 | 项目级定义 | 当前项目独立角色副本，可增删改、从角色库引用、从模版加载 |
| 工作流模版 | 项目级定义 | 只引用工作流模版，模版本体仍在「工作流 → 工作流模版管理」维护 |

项目详情下方的页签只管理实例：成员权限、任务清单、工作流、项目日报、历史记录。定义与实例不得混在同一层页签中。

### 5.3 负责人 / 归属

| 对象 | 统一叫法 | 说明 | 禁止 |
| --- | --- | --- | --- |
| 项目 | 负责人 | 对项目交付负责的人 | 界面显示 Owner |
| 工作区 | 工作区负责人 | 工作区成员角色 owner | 与项目负责人混用 |
| 任务 / 节点 | 负责人 | 任务或节点的执行责任人 | 操作人、Owner |
| AI 伙伴 | 归属 | AI 伙伴归属的账号 | 负责人 |

### 5.4 状态词与色调

| 语义分组 | 状态词 | 色调 | 说明 |
| --- | --- | --- | --- |
| 进行类 | 进行中 / 运行中 | accent | 正在推进 |
| 关注类 | 待验收 / 需留意 / 待命 | warning | 需要关注但未失败 |
| 完成类 | 已完成 / 健康 / 启用 | success | 正常终态 |
| 风险类 | 阻塞 / 风险 / 失败 / 停用 | error | 需要处理 |
| 中性类 | 未开始 / 等待中 / 已取消 / 归档 / 空闲 | neutral | 非异常非完成 |

强制规则：

- 健康度禁止使用「关注」，统一为「需留意」，避免与关注动作同词；「关注」只表示 follow。
- 同一状态词在不同模块必须使用同一色调，不得项目里用橙色、工作流里用灰色。

## 6. 交互逻辑规范

### 6.1 列表选择与详情

1. 首次进入自动选中第一项；
2. 点击列表项立即切换选中态，详情进入 loading；
3. 详情失败时保留列表与选中态，在详情区显示错误 + 重试；
4. 切换项目 / 页签时关闭当前弹窗并清空临时草稿；
5. 搜索无结果时保留搜索框与筛选条件，展示空态。

### 6.2 两种编辑范式（MUST）

**A. 直接保存**：单对象、低影响、可再次修改。

适用：项目基础信息、成员的项目角色、单条任务字段、单条日报。

流程：打开弹窗 → 修改 → 保存 → 关闭 → Toast → 局部刷新。

**B. 草稿 → 确认生效**：批量、跨对象、覆盖式、不可逐条撤销。

适用：项目角色整组变更、项目模版角色清单、工作流模版版本。

流程：

```text
编辑 → 形成草稿 → 展示差异（新增/修改/移除）
     → 点击「确认生效」→ 影响预览（受影响成员/任务/工作流）
     → 二次确认 → 提交 → 刷新 → 清空草稿
```

规则：

- 草稿态必须可见：页签或标题带「· 草稿」，底部出现操作条；
- 差异条格式：`新增 X · 修改 Y · 移除 Z`；
- 覆盖式生效，必须携带版本号（revision）防止并发覆盖；
- 取消编辑要恢复生效集；
- 有未确认草稿时，关闭弹窗 / 切页 / 切项目必须先弹出放弃确认。

### 6.3 危险操作

- 删除、移除、停用、覆盖、批量变更：必须二次确认；
- 确认文案包含对象名与影响范围；
- 危险操作按钮使用 danger；
- 执行中禁用按钮，禁止重复提交；
- 成功后 Toast，失败后保留弹窗与用户输入。

### 6.4 未保存守卫

以下动作前检查 `dirty`：关闭弹窗、切换页签、切换项目、关闭详情、跳转其他模块。

三种处理：

1. 无改动：直接关闭；
2. 有改动：弹确认框（继续编辑 / 放弃改动）；
3. 复杂草稿：额外提供「保存草稿」入口（若产品支持持久草稿）。

### 6.5 权限与只读

- **无权限**：优先隐藏入口（例如非管理员看不到「管理」按钮）；
- **需解释**：使用只读样式 + 说明，而不是 disabled 输入框；
- **平台级信息**在项目 / 工作区页面一律只读；
- 只读状态不能通过前端隐藏绕过，接口必须二次校验；
- 权限判断统一来源：`viewer.canManage` 或平台管理员。

### 6.6 异步状态

每个页面至少维护四个状态：

| 状态 | 表现 |
| --- | --- |
| `loading` | 骨架或居中加载文案 |
| `ready` | 正常内容 |
| `empty` | 空态组件 + 下一步 |
| `error` | 错误条 + 重试 |

每个写操作额外维护 `busy`：按钮 disabled，文案可改为「保存中…」。

**失败时不清空表单**，让用户可以修正后重试。

### 6.7 反馈时长

| 类型 | 时长 |
| --- | --- |
| 成功 Toast | 2600ms |
| 普通提示 | 3000ms |
| 错误提示 | 4000ms（复杂错误手动关闭） |
| 草稿提示 | 6000ms 或常驻 |
| 行高亮 | 2400ms |

### 6.8 刷新与轮询

- 每个数据模块提供显式刷新按钮，图标按钮必须有 `aria-label`；
- 运行中数据才轮询：任务执行中 2.5s，文档生成 8s；
- 无运行中任务时停止轮询；
- 刷新只更新该模块，不整页 reload。

### 6.9 跨模块跳转（MUST）

平台使用事件与全局上下文通信：

| 场景 | 约定 |
| --- | --- |
| 切换全局路由 | `pluginmax:navigate` → `{ route }` |
| 路由点击（可回到根视图） | shell 发出 `pluginmax:route-select` |
| 深链打开详情 | 直接调用 `window.__pluginmaxShell.setRoute(route)`，再写 pending 上下文 |
| 插件内详情跳转 | `pluginmax:collab-navigate` → `{ plugin, ...id, workspaceId }` |
| 关注状态变化 | `pluginmax:follow-change` |

**深链注意**：`pluginmax:navigate` 会触发目标页的 route-select 重置，从而清掉 pending 详情。深链必须走 `setRoute`，不要用 navigate 事件。

示例：

```js
window.__pluginmaxPendingTask = { taskId, workspaceId };
window.__pluginmaxShell.setRoute("task");
```

### 6.10 返回上下文

- 详情关闭 → 回到列表并保留搜索、筛选、滚动位置；
- 从其他模块跳入详情 → 记录来源，关闭时提供「返回 AI 伙伴 / 返回工作台」；
- 来源信息通过 pending 上下文传递，不写进 URL hash 之外的隐式状态。

### 6.11 拖拽（工作台）

- 6 等分栅格，宽度档位 1～6 列；
- 高度 190～900px；
- 标题行整体作为拖拽把手，操作按钮不响应拖拽；
- 拖拽中卡片 `opacity .48` + accent 边框；
- 落点区 accent 边框 + 7% 背景；
- 布局持久化到 `localStorage`，支持多套布局、默认布局、恢复默认。

### 6.12 局部管理模式（MUST）

当用户点击区块内的「管理成员」「管理角色」等操作时，只切换该区块为编辑态，不得替换整个右侧详情。

必须保留：

- 页面头与项目基本信息；
- 指标摘要；
- 页签栏；
- 其他区块内容。

只有当前区块的内容在「只读 / 管理」之间切换；退出管理后回到原只读态。切换页签或切换项目时自动退出管理态。

管理态标题与只读态保持一致（例如都叫「成员权限」），不重复项目名称、项目编号、成员数量，也不额外增加解释性提示段；成员数量已经由指标卡和页签承载。

## 7. 文案规范

### 7.1 语言

- 简体中文为主，专有名词保留英文（AI Teammate、Owner、Markdown）；
- 同一概念只用一个词，禁止「项目 / 工作区」「AI 伙伴 / AI Teammate」混用；
- 不使用感叹号、不使用口语化夸张表达。

### 7.2 标题

- 页面标题：名词短语（项目管理、工作流、AI 伙伴）；
- 区块标题：名词短语（成员权限、项目角色清单、历史记录）；
- 弹窗标题：动作 + 对象（编辑项目成员权限、添加项目成员）。

### 7.3 按钮

- 2～4 个字，动词开头；
- 同一弹窗内两个按钮语义必须区分（保存变更 / 确认生效 / 取消）；
- 危险按钮写具体动作（移除成员），不要只写「确定」。

### 7.4 空态

格式：`当前没有什么 + 用户可以做什么`。

- 好：`当前项目还没有项目角色。可以从模版加载、复用其他项目，或手动添加角色。`
- 差：`暂无数据`

### 7.5 错误

格式：`发生了什么 + 为什么 + 怎么办`。

- 好：`保存失败：没有权限修改项目角色。请联系项目负责人。`
- 差：`操作失败`

## 8. 可访问性

- 图标按钮必须有 `aria-label`；
- 切换类按钮使用 `aria-pressed`；
- 页签使用 `role="tablist"` / `role="tab"` / `aria-selected`；
- 弹窗使用 `role="dialog"` + `aria-modal="true"`；
- Esc 关闭弹窗与下拉；
- 所有交互元素可 Tab 聚焦，焦点样式清晰；
- 可点击行支持 Enter / Space；
- 文本与背景对比度不低于 4.5:1。

## 9. 工程实现约定

### 9.1 模块前缀（MUST）

每个插件使用独立 CSS 前缀，禁止全局选择器：

| 模块 | 前缀 |
| --- | --- |
| shell | `pmx-` |
| task | `pmtask-` |
| project | `pmproj-` |
| workflow | `pmwf-` |
| workbench | `pmwb-` |
| teammate | `pmtm-` |
| meeting | 暂无类名前缀（内联 style 对象，建议迁移到 `pmmtg-`） |

> `dsh-collab-identity` / `employee` / `roles` / `space` 目前同样以内联 style 对象实现，没有类名前缀。这些模块的取值必须与本规范一致；新页面优先使用前缀类名，便于统一维护。

样式必须写在模块根节点的作用域下，例如 `.pmproj *{box-sizing:border-box}`。

### 9.2 技术形态

- 使用 `React.createElement`（`h`），不使用 JSX；
- 样式以 `<style>{styles}</style>` 注入，作用域限定在前缀；
- 通过 `window.__ModuleLoader__.load` 注册模块；
- 不引入第三方 UI 组件库；
- 图标使用内联 SVG，不加载图标字体。

### 9.3 主题

- 必须同时适配深色与浅色主题；
- 禁止写死不透明深色背景；
- 使用 `color-mix` 生成浅色底；
- 主题切换由 shell 写入 `body` 的令牌驱动，模块不监听主题事件。

### 9.4 复用优先（MUST）

1. 先查 4.16 的组件清单，确认是否已有可复用实现。
2. 同一结构出现第 3 次，必须抽成共享组件；不允许继续复制。
3. 共享组件只暴露语义参数，不暴露任意样式覆盖。
4. 页面层禁止写死间距、字号、颜色；这些由组件内部决定。
5. 新模块接入时先完成三件事：套用 PageHeader、套用 SplitLayout、套用 DetailHeader。
6. 代码评审必须检查：是否重复实现已有组件、是否复制布局、是否新增同义不同形的控件。

## 12. 附：标准组件代码骨架

### 12.1 页面

```js
h("section", { className: "pmxxx" },
  h("div", { className: "pmxxx-head" },
    h("div", null,
      h("h1", null, "页面标题"),
      h("div", { className: "pmxxx-sub" }, "一句话说明"),
    ),
    h("div", { className: "pmxxx-head-actions" },
      h("button", { className: "pmxxx-btn secondary" }, "次要操作"),
      h("button", { className: "pmxxx-btn" }, "主操作"),
    ),
  ),
  h("div", { className: "pmxxx-layout" }, /* 内容 */),
)
```

### 12.2 空态

```js
h("div", { className: "pmxxx-empty" },
  "当前项目还没有成员。点击「添加成员」从平台用户中选择。",
)
```

### 12.3 弹窗

```js
h("div", { className: `pmxxx-mask ${open ? "open" : ""}` },
  h("div", {
    className: "pmxxx-modal",
    role: "dialog",
    "aria-modal": "true",
    "aria-label": "编辑项目成员权限",
  },
    h("div", { className: "pmxxx-modal-head" },
      h("h2", null, "编辑项目成员权限"),
      h("button", { className: "pmxxx-btn secondary small", onClick: close }, "关闭"),
    ),
    /* 表单 */
  ),
)
```

### 12.4 草稿操作条

```js
h("div", { className: "pmxxx-draft-bar" },

    h("button", { className: "pmxxx-btn secondary small", onClick: discard }, "取消编辑"),
    h("button", { className: "pmxxx-btn small", onClick: confirm }, "确认生效"),
  ),
)
```
