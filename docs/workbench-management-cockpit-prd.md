# 工作台与管理驾驶舱 PRD

> 文档状态：v1.0  
> 适用页面：工作台 Workbench  
> 交互参考：[task-management-demo.html](./demos/task-management-demo.html)  
> 目标读者：产品、设计、前端、后端、测试及后续实现 Agent

## 1. 背景

当前用户的任务、工作流、会议、指标和供应链风险分散在不同页面。用户进入系统后，需要主动在多个入口之间切换，才能知道：

- 过去一段时间发生了什么；
- 哪些事项需要我处理或验收；
- 哪些任务、工作流需要持续关注；
- 当前业务指标和供应链风险是否正常；
- 哪些会议结论会直接影响下一步动作。

工作台的目标是把这些信息聚合为一个日常操作的主 Landing Page。它不替代任务管理、工作流、会议和指标详情页，而是作为统一的发现、判断和跳转入口。

工作台包含两个模式：

1. `我的工作台`：面向个人贡献者和管理者的个人执行视图；
2. `管理驾驶舱`：面向管理者的全局经营与组织视图。

本期必须完整实现“我的工作台”；“管理驾驶舱”必须保留正式入口和页面容器，但不要求在首版实现完整业务模块。

## 2. 产品目标

1. 用户打开工作台后，5 秒内能识别需要自己处理的最高优先级事项。
2. 每日简报能明确区分进展、结论、数据异常和待决策，并支持 AI 决策建议。
3. 我的待办与重点关注使用一致的卡片、信息和跳转方式。
4. 用户可以自定义工作台模块顺序、宽高和布局，并保存多套布局。
5. 默认布局可恢复，且不会被日常拖拽永久覆盖。
6. 所有模块支持显式刷新，并展示数据更新时间和刷新状态。
7. 所有列表项都能跳转到任务、工作流、会议或指标详情，并可返回工作台原位置。
8. 管理驾驶舱拥有稳定的模式入口，为后续全局分析能力保留扩展空间。

## 3. 成功指标

- 工作台 → 待办详情点击率不低于 35%。
- 每日简报待决策事项的 AI 建议展开率不低于 25%。
- 需要处理事项从进入工作台到打开详情的平均耗时低于 20 秒。
- 至少 30% 的活跃用户使用过自定义布局或保存布局。
- 刷新失败率低于 1%，失败时必须展示可重试反馈。
- 跳转详情后返回工作台，模块顺序、宽高、滚动位置和当前布局不丢失。

## 4. 非目标

本期不做：

- 在工作台内直接完成复杂任务编辑；
- 替代任务管理、工作流详情、会议详情或完整 BI 系统；
- 任意用户创建跨组织共享的公开仪表盘；
- 管理驾驶舱的完整指标建模与权限体系；
- 自动执行 AI 决策建议，所有建议必须由用户明确确认；
- 前端绕过服务端权限进行数据过滤。

## 5. 用户与权限

| 角色 | 主要诉求 | 工作台权限 |
| --- | --- | --- |
| 普通成员 | 处理个人待办、查看会议与简报 | 只看本人任务、关注对象和有权访问的工作区数据 |
| 管理者 | 查看团队风险、流程阻塞和经营指标 | 在“我的工作台”查看个人视图；后续在驾驶舱查看授权范围全局数据 |
| 项目 Owner | 跟踪项目风险与流程 SLA | 可查看所属项目、工作流实例和项目指标 |
| 管理员 | 配置指标、布局和全局权限 | 可管理指标定义和平台配置，不因管理员身份自动获得业务数据权限 |
| Agent | 提供简报、建议、摘要和归因 | 只能通过已授权工具读写，不得绕过用户确认执行决策 |

权限由服务端最终校验。前端隐藏模块或按钮只用于体验优化，不作为安全边界。

## 6. 信息架构

### 6.1 页面入口

工作台是中间操作区的全局视图，不改变 DSH 主布局。

页面顶部包含：

1. 左侧模式切换：
   - `我的工作台`
   - `管理驾驶舱`
2. 右侧全局操作：
   - 布局切换与布局管理；
   - 恢复默认布局。

当前模式必须通过 `aria-pressed` 或等价语义表达。切换模式不刷新整个应用，只切换对应工作台容器。

### 6.2 我的工作台模块

默认模块及顺序：

1. 核心指标
2. 每日简报
3. 我的待办
4. 重点关注
5. 会议纪要
6. 供给例外
7. 供应商风险

默认六列宽度：

| 模块 | 默认宽度 |
| --- | --- |
| 核心指标 | 6/6 |
| 每日简报 | 6/6 |
| 我的待办 | 4/6 |
| 重点关注 | 2/6 |
| 会议纪要 | 4/6 |
| 供给例外 | 2/6 |
| 供应商风险 | 4/6 |

页面使用 6 等分网格。用户调整后的小数比例必须映射为以下宽度档位：

`1/6、1/3、1/2、2/3、5/6、1`

### 6.3 管理驾驶舱

首版只实现：

- 模式入口；
- 选中态；
- 占位容器；
- 明确的“后续能力”说明；
- 不发起驾驶舱业务数据请求。

后续阶段规划以下区域：

1. 经营指标：营收、毛利、现金流、库存和交付履约；
2. 项目与流程：项目健康度、SLA、逾期节点和阻塞原因；
3. 组织与资源：负载、产能、瓶颈角色和跨团队依赖；
4. 供应链：供应商绩效、单源风险、价格达成和覆盖天数；
5. 风险矩阵：按影响、概率、趋势和责任人聚合；
6. 管理动作：下钻、对比、导出、订阅和指派跟进。

## 7. 核心概念

### 7.1 模块 Module

工作台内可独立排序、调整宽度和刷新的一块业务内容。

每个模块必须声明：

```ts
type WorkbenchModule = {
  id: "metrics" | "brief" | "todo" | "focus" | "meeting-minutes" | "control" | "supplier";
  title: string;
  defaultCols: 1 | 2 | 3 | 4 | 5 | 6;
  minHeight: number;
  refreshable: boolean;
};
```

### 7.2 布局 Layout

一套包含模块顺序、模块宽度和模块高度的命名快照。

```ts
type WorkbenchLayout = {
  id: string;
  name: string;
  order: WorkbenchModule["id"][];
  modules: Record<WorkbenchModule["id"], {
    cols: 1 | 2 | 3 | 4 | 5 | 6;
    height: number | null;
  }>;
};
```

### 7.3 当前布局 Active Layout

用户当前正在使用的命名布局。未保存的临时拖拽结果可以写入 `current` 运行时快照，但不得覆盖默认布局基准。

### 7.4 默认布局 Default Layout

“恢复默认布局”使用的基准布局。必须满足：

- 同一时间只能有一个默认布局；
- 默认布局不能被直接删除；
- 默认布局的基准数据不能被普通拖拽覆盖；
- 用户可将任意已保存布局设为默认；
- 点击恢复后，当前布局切换为该默认布局，并清除临时运行态。

### 7.5 数据新鲜度

每个模块应返回：

- `updatedAt`：数据最近更新时间；
- `staleAt`：可选，超过该时间进入过期态；
- `refreshable`：是否允许手动刷新；
- `sourceCount`：可选，聚合数据源数量。

## 8. 全局布局与交互

### 8.1 模块标题栏

标题栏统一为单行结构：

```text
[标题] [数量/摘要]                           [状态] [操作按钮] [刷新]
```

要求：

- 取消六点拖拽图标；
- 标题栏除按钮和表单控件外，均为拖拽热区；
- 光标为 `grab`，拖动中为 `grabbing`；
- 刷新按钮位于操作区最右侧；
- 标题栏在 1/3 宽度下不换行；
- 数量文字使用弱化样式，字号小于标题；
- 标题过长时省略，不允许挤压刷新按钮；
- 点击按钮、下拉、开关或可点击控件不得触发拖动。

### 8.2 拖拽排序

- 按住模块标题栏拖动；
- 拖动时模块半透明，并显示目标插入位置；
- 释放后保存到当前布局；
- 模块顺序变化后，刷新页面必须保留；
- 拖拽过程中不得触发模块内部点击事件。

### 8.3 调整宽高

宽度：

- 通过模块右边缘拖拽；
- 吸附到六档宽度；
- 最小 1/6，最大 1；
- 重新加载后宽度不变。

高度：

- 通过模块右下角调整；
- 最小高度 190px；
- 最大高度 900px；
- 未调整高度时由内容自适应；
- 调整后模块内部独立滚动，不撑破工作台网格。

### 8.4 刷新

每个模块右上角提供刷新按钮：

- 核心指标、每日简报、我的待办、重点关注、会议纪要、供给例外、供应商风险；
- 点击后按钮进入 `refreshing` 状态，图标旋转；
- 刷新期间按钮禁用，防止重复请求；
- 成功后更新数据、更新时间和 toast；
- 失败后保留旧数据，展示错误 toast 和重试入口；
- 每日简报复用同一刷新语义，但需要额外展示生成中的文案。

### 8.5 跳转与返回

点击模块项或详情按钮后：

- 任务 → 任务管理详情；
- 工作流 → 工作流详情；
- 会议 → 会议纪要详情；
- 指标 → 指标下钻；
- 供给例外 → 关联任务、工作流或归因详情；
- 供应商风险 → 供应商详情。

返回工作台时必须恢复：

- 当前工作台模式；
- 当前布局；
- 模块顺序与宽高；
- 页面滚动位置；
- 最近打开的模块状态（如 AI 建议展开状态可暂不恢复）。

## 9. 布局管理

### 9.1 入口

工作台顶部右侧提供“布局切换”图标按钮。点击后打开布局管理弹窗。

不再使用独立的布局下拉框，布局名称和切换入口统一收进弹窗。

### 9.2 弹窗能力

弹窗包含：

1. 输入布局名称；
2. `保存当前布局`；
3. 已保存布局列表；
4. 当前布局标识；
5. `设为默认`；
6. `删除`；
7. 关闭按钮。

保存规则：

- 每次保存必须由用户手动输入名称；
- 名称为空时阻止保存并聚焦输入框；
- 名称重复时提示“布局名称已存在，请换个名称”；
- 保存成功后，新布局成为当前布局；
- 保存内容包含当前顺序、宽度和高度。

切换规则：

- 点击布局名称立即切换；
- 切换后更新工作台和当前布局状态；
- 切换不修改默认布局。

默认规则：

- 默认布局显示“默认”标识；
- 默认布局的删除按钮禁用；
- 点击其他布局的“设为默认”后立即生效；
- 恢复默认布局时使用该基准。

删除规则：

- 删除前必须二次确认；
- 默认布局不能删除；
- 删除当前布局时，切换到默认布局；
- 删除其他布局不影响当前工作台。

### 9.3 本地持久化模型

Demo 与前端本地状态可使用以下结构：

```json
{
  "layouts": [
    {
      "id": "factory-default",
      "name": "默认工作台",
      "order": ["metrics", "brief", "todo", "focus", "meeting-minutes", "control", "supplier"],
      "modules": {
        "metrics": { "cols": 6, "height": null },
        "brief": { "cols": 6, "height": null },
        "todo": { "cols": 4, "height": null },
        "focus": { "cols": 2, "height": null },
        "meeting-minutes": { "cols": 4, "height": null },
        "control": { "cols": 2, "height": null },
        "supplier": { "cols": 4, "height": null }
      }
    }
  ],
  "defaultId": "factory-default",
  "activeId": "factory-default",
  "current": null
}
```

实现要求：

- 存储 key 建议为 `dsh-workbench-layouts-v1`；
- 存储损坏或结构不合法时回退到出厂默认布局；
- 模块 ID 非法时忽略，不得导致页面崩溃；
- 宽度取最接近的合法档位；
- 高度限制在 190-900px；
- 本地存储只保存 UI 偏好，不保存业务数据。

## 10. 我的工作台模块需求

### 10.1 核心指标

目标：让用户快速判断当前供应链采购业务是否处于正常状态。

默认指标：

- OTIF；
- 库存周转天数；
- 供应商准时率；
- 采购价格达成；
- 供应风险指数（可选）。

展示：

- 指标名称；
- 当前值；
- 单位；
- 趋势；
- 目标或阈值；
- 迷你趋势图；
- 数据更新时间。

配置：

- 点击齿轮打开“配置核心指标”；
- 最多选择 5 项；
- 至少选择 1 项；
- 保存后立即刷新模块，无需整页刷新；
- 指标选择持久化。

交互：

- 点击指标卡进入指标下钻；
- 刷新按钮重新拉取指标；
- 无数据时展示空状态，不用 0 伪装；
- 指标过期时显示“数据可能延迟”。

### 10.2 每日简报

目标：聚合过去 N 小时需要用户知晓、关注或决策的事项。

头部：

- 标题：每日简报；
- 周期信息：过去 N 小时 · AI 生成；
- 生成时间范围和更新频次；
- 更新频次设置；
- 刷新按钮位于最右侧。

简报内容分类：

| 类型 | 说明 | 操作 |
| --- | --- | --- |
| 进展 | 已完成或推进中的事项 | 查看关联详情 |
| 数据异常 | 指标、库存、交付等异常 | 查看归因 |
| 结论 | AI 或会议形成的确定结论 | 查看明细 |
| 待决策 | 需要用户确认的事项 | AI 建议、处置、跳转 |

待决策交互：

- 点击 `AI建议` 在原描述正下方展开；
- 建议宽度必须与描述列一致；
- 展开后不出现大面积空白；
- 再次点击收起；
- 建议必须说明结论、依据和影响；
- `处置` 跳转到关联任务、工作流或决策详情；
- AI 只提供建议，不自动执行。

更新频次：

- 支持每天 08:00；
- 支持每天 08:00 / 13:00；
- 支持每 4 小时；
- 支持每周一 08:00；
- 支持静默窗口；
- 紧急 P0 供给中断可按策略绕过静默窗口。

状态：

- 生成中：禁用刷新，显示生成中；
- 已生成：展示最近生成时间；
- 无数据：展示“当前周期没有新增简报”；
- 失败：保留上次成功内容，并提供重试。

### 10.3 我的待办

目标：聚合当前用户的待处理与待验收任务。

数据范围：

- 当前用户的 `待处理`；
- 当前用户的 `待验收`；
- 不包含已归档任务；
- 只包含用户有权访问的任务。

排序：

1. 优先级：P0、P1、P2、P3；
2. 截止时间升序；
3. 任务 ID 稳定排序。

展示字段：

- 任务 ID；
- 标题；
- 优先级；
- 状态；
- 来源类型：工作流生成 / 常规任务；
- 工作区；
- 接收人；
- 截止时间；
- 详情按钮。

交互：

- 点击整行或详情按钮进入任务详情；
- 工作流生成任务与常规任务样式保持一致，仅用来源标签区分；
- 返回后恢复工作台位置；
- 空状态说明没有待处理或待验收事项。

### 10.4 重点关注

目标：展示用户主动关注的任务和工作流。

数据范围：

- 已关注任务；
- 已关注工作流；
- 已归档任务不显示；
- 用户无权限的数据不显示。

展示：

- 与“我的待办”使用同一套 `todo-item` 结构和操作区；
- 任务：任务 ID、标题、优先级、状态、关注任务、工作区、接收人、截止时间；
- 工作流：工作流 ID、标题、状态、关注工作流、工作区、更新时间；
- 右上或尾部提供关注/取消关注操作；
- 标题区展示关注对象数量。

交互：

- 点击 `详情` 跳转对应详情；
- 点击关注按钮切换关注状态；
- 取消关注后从列表移除；
- 关注操作成功后其他页面的关注按钮必须同步状态；
- 工作流和任务都支持关注。

### 10.5 会议纪要

目标：展示最近需要用户知晓的会议核心结论摘要。

展示字段：

- 会议 ID；
- 会议标题；
- 核心结论；
- 待确认事项；
- 会议状态；
- AI 摘要标识；
- 工作区；
- 参与者数量；
- 更新时间；
- 详情按钮。

交互：

- 点击整行或详情按钮进入会议详情；
- 会议详情中展示完整会议纪要；
- 头部不显示“过去 24 小时”字样，只保留模块数量、更新时间和刷新；
- 列表为空时展示“暂无会议纪要”。

### 10.6 供给例外

目标：集中展示物料缺口、供应商风险和关键流程阻塞。

展示字段：

- 严重度：高、中、关注；
- 标题；
- 建议动作；
- Owner；
- 决策时间或 SLA；
- 影响范围；
- 关联任务或工作流；
- 操作按钮。

交互：

- `归因` 打开异常归因说明；
- `处置` 创建或打开处置任务；
- `查看流程` 打开关联工作流；
- `验收` 打开关联任务；
- 覆盖率区域展示关键物料的当前覆盖天数；
- 风险达到阈值时使用红色或琥珀色提示。

### 10.7 供应商风险

目标：展示供应商绩效和韧性风险。

展示字段：

- 风险评分；
- 供应商名称；
- 风险类型；
- 承诺完成率或质量指标；
- 采购份额；
- 建议动作；
- 数据更新时间。

底部说明：

- 单源物料占比；
- 无合格备用产能的物料数量；
- 建议复盘或备选产能动作。

交互：

- 点击供应商项进入供应商详情；
- 支持按高、中、关注风险等级识别；
- 刷新后更新最近更新时间；
- 无权限时整块隐藏或展示无权限说明。

## 11. 管理驾驶舱设计要求

### 11.1 首版实现

选中“管理驾驶舱”后：

- 隐藏我的工作台全部模块；
- 显示独立驾驶舱容器；
- 不请求个人工作台模块数据；
- 显示预留说明；
- 保持模式切换可用；
- 不影响个人工作台布局和状态。

### 11.2 后续产品方向

管理驾驶舱面向管理者，强调：

- 全局视角；
- 横向比较；
- 趋势与异常；
- 组织和资源负载；
- 责任追踪；
- 下钻到项目、流程、任务和个人。

建议的信息层级：

1. 顶部筛选：组织、工作区、时间范围、业务线、供应商；
2. 摘要区：最需要管理的 3-5 个结论；
3. 指标区：经营、交付、资源、风险、成本；
4. 对比区：同比、环比、目标差距、同组织排名；
5. 风险区：按影响和概率排序；
6. 下钻区：项目、流程、供应商、责任人和动作。

首版不得因为预留入口而提前实现未确认的驾驶舱数据模型。

## 12. 数据与接口建议

建议提供一个聚合接口，避免工作台首屏发起大量独立请求：

```ts
type WorkbenchPayload = {
  userId: string;
  generatedAt: string;
  brief: BriefModulePayload | null;
  metrics: MetricsPayload;
  todos: TodoItemPayload[];
  focus: FocusItemPayload[];
  meetings: MeetingMinutesPayload[];
  supplyExceptions: SupplyExceptionPayload[];
  supplierRisks: SupplierRiskPayload[];
};
```

接口要求：

- 服务端完成权限过滤；
- 服务端完成优先级和截止时间排序；
- 所有时间返回 ISO 8601 或 UTC，前端本地化；
- 返回 `updatedAt` 和可选 `staleAt`；
- 单个模块失败时返回模块级错误，不导致整页失败；
- 支持模块级刷新参数；
- 不在 UI 主信息中暴露内部 UUID。

## 13. 状态与异常

每个模块必须处理以下状态：

| 状态 | 行为 |
| --- | --- |
| loading | 骨架屏或局部 loading，不阻塞其他模块 |
| success | 展示内容和更新时间 |
| empty | 解释为什么为空，必要时提供创建入口 |
| stale | 保留旧数据，展示“数据可能延迟” |
| refreshing | 保留旧数据，图标旋转，按钮禁用 |
| partial error | 模块内错误提示，其他模块正常 |
| auth error | 展示无权限说明，不泄露数据 |

统一错误重试要求：

- 失败后旧内容不消失；
- toast 或模块内提示必须可读；
- 提供重试按钮；
- 连续失败不得自动无限重试。

## 14. 可访问性

- 模式切换使用 tablist 语义或按钮 `aria-pressed`；
- 图标按钮必须有 `aria-label` 和 `title`；
- 刷新状态使用 `aria-busy` 或等价语义；
- 键盘 `Tab` 可访问所有操作按钮；
- `Enter` 和 `Space` 可打开当前可点击列表项；
- 拖拽不得成为唯一定位方式，至少保留布局管理的可配置入口；
- 焦点状态清晰可见；
- 颜色不是区分风险等级的唯一方式，必须同时提供文字或图标。

## 15. 埋点建议

记录以下事件：

- `workbench_mode_switch`：personal / cockpit；
- `workbench_layout_save`：布局名称、模块数量；
- `workbench_layout_switch`：来源布局、目标布局；
- `workbench_layout_set_default`；
- `workbench_layout_reset`；
- `workbench_module_refresh`：模块 ID、结果、耗时；
- `workbench_brief_decision_expand`；
- `workbench_brief_decision_click`；
- `workbench_item_open`：item type、target page；
- `workbench_follow_toggle`：task / workflow、关注或取消关注。

埋点不得记录敏感会议正文、任务描述或供应商价格明细。

## 16. 验收标准

### 16.1 工作台壳层

- [ ] “我的工作台”和“管理驾驶舱”可切换，状态不会互相污染。
- [ ] 工作台顶部不再显示独立布局下拉框。
- [ ] 右上角布局管理和恢复默认按钮可用。
- [ ] 管理驾驶舱只展示预留入口，不请求业务数据。

### 16.2 模块交互

- [ ] 七个模块均支持标题栏拖拽排序。
- [ ] 标题栏按钮不会触发拖拽。
- [ ] 每个模块支持六档宽度拖拽。
- [ ] 每个模块支持高度调整。
- [ ] 每个模块右上角存在刷新按钮，且刷新按钮位于最右侧。
- [ ] 1/3 宽度下模块标题、更新状态和刷新按钮保持单行。
- [ ] 数量文字比标题小，且不会挤压操作区。

### 16.3 布局管理

- [ ] 当前排布可作为命名布局保存。
- [ ] 支持保存多个布局。
- [ ] 支持切换布局。
- [ ] 支持设置默认布局。
- [ ] 默认布局不可删除。
- [ ] 删除布局需要确认。
- [ ] 恢复默认布局使用指定默认布局。
- [ ] 页面刷新后保留当前布局、顺序、宽度、高度和默认布局。
- [ ] 本地存储损坏时回退到默认布局而不白屏。

### 16.4 模块业务

- [ ] 每日简报展示进展、数据异常、结论和待决策。
- [ ] 待决策 AI 建议展开后紧贴描述下方，且宽度与描述一致。
- [ ] 简报支持手动刷新和更新频次设置。
- [ ] 我的待办包含“待处理”和“待验收”，并按 P0-P3 排序。
- [ ] 我的待办和重点关注使用一致的结构与操作。
- [ ] 任务和工作流支持关注与取消关注。
- [ ] 会议纪要展示结论和待确认事项，并可进入详情。
- [ ] 核心指标支持配置并最多展示 5 项。
- [ ] 供给例外和供应商风险支持跳转和刷新。

## 17. 开放问题

1. 每日简报默认周期是否固定为过去 24 小时，还是按用户时区和频次动态计算？
2. 重点关注是否需要支持分组、置顶和自定义排序？
3. 默认布局是每个用户独立，还是管理员可以下发组织级默认布局？
4. 模块刷新是强制重算 AI 摘要，还是仅拉取最新缓存结果？
5. 供给例外和供应商风险是否需要工作区级、组织级或供应商级过滤？
6. 管理驾驶舱的数据范围与权限能否复用现有项目角色，还是需要新的管理角色？
