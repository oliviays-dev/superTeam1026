# 项目管理模块 GUI 测试计划（dsh-collab-project）

> 目标：验证「项目管理」入口、项目清单/详情、成员权限、任务与工作流联动、项目日报、
> 项目模版维护，以及「平台级账号与角色权限只读」的约束。
>
> 环境隔离：本文使用独立 `DSH_HOME`，不要复用正在运行的 `.tmp/dsh-home`（33124）。

## 1. 环境准备

| 步骤 | 命令 / 操作                                                                                                                           | 预期                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 1    | `cd dsh-pluginmax && ./scripts/bootstrap.sh`                                                                                          | 依赖与上游 DSH 构建完成                                 |
| 2    | `PLUGINMAX_SMOKE_HOME="$PWD/.tmp/project-smoke-home" PLUGINMAX_SMOKE_PORT=33119 ./scripts/smoke.sh`                                   | 全部接口冒烟通过，含项目管理检查段                      |
| 3    | `DSH_HOME="$PWD/.tmp/project-smoke-home" node vendor/deepseek-harness/apps/cli/lib/bin.js --profile pluginmax --no-open --port 33121` | 终端输出带 token 的 `http://127.0.0.1:33121/?token=...` |
| 4    | 浏览器打开该 URL，跳过内测声明与 API Key 提示，用 `admin / password-123` 登录                                                         | 进入工作台，左侧导航出现「项目管理」                    |

需要全新环境时，先按 `scripts/install-profile.sh` 的插件清单把 `dsh-collab-project`
加入目标 `DSH_HOME` 的 `pluginmax` profile。

## 2. 用例

### P1 导航与项目清单

1. 点击左侧「项目管理」。
2. 期望：页头为「项目管理 / 项目清单、成员权限、任务、工作流、项目日报与项目模版」，
   右上角有「项目模版」「新建项目」；左列为「项目列表」清单及数量单位，条目显示首字母、名称、
   编码 · Owner 与状态 pill。
3. 点选不同项目名，期望右侧详情切换到对应项目（标题、编码、Owner、进度、事实卡与页签计数同步）。
4. 期望页面内只有本模块的一个项目页（不出现工作台遗留的「共 N 个项目 · 已关注 M 个」列表页）。
5. 在搜索框输入名称/编码/Owner/状态片段，期望清单实时过滤，计数同步变化。
6. 切换左侧栏「仅看已加入 / 平台全量」，期望清单范围跟随共享范围 store（与其他模块一致）。

### P2 项目详情

1. 选中一个项目。
2. 期望：标题行显示状态与健康度 pill；元信息行显示编码、Owner、起止日期、进度；
   说明、三项事实卡（项目成员 / 活跃任务 / 关联工作流）与四个页签（成员权限 / 任务清单 /
   工作流 / 项目日报）计数正确。
3. 点击「关注」，期望按钮变为「已关注」，工作台「重点关注」出现该项目。

### P3 项目设置（项目负责人/平台管理员）

1. 点击「项目设置」，期望弹窗标题为「项目设置」，包含「基础信息」「项目角色」两个页签。
2. 在「基础信息」修改状态、健康度、进度、起止日期、说明，选择项目负责人后保存。
3. 期望：详情即时刷新；把负责人改为非项目成员时接口返回 400（提示不合法）。
4. 用普通成员账号登录：不可见「项目设置」「管理成员」「更新日报」，仅可查看。

### P4 项目设置 - 项目角色

1. 打开「项目设置」→「项目角色」。
2. 期望：「项目角色清单」右侧并列「从模版加载」「复用其他项目」「添加角色」；
   不存在「应用模版」按钮。
3. 点「添加角色」：从角色库预填或从空白填写名称/标识/分类/权限/说明后保存；期望列表出现
   「新增」标记和底部「新增 1 · 修改 0 · 移除 0」草稿栏，但成员 chip 暂不变化。
4. 点「从模版加载」：先展示模版列表；选中该模版后，如果当前草稿有改动，才弹出
   「放弃角色草稿？」并说明会加载哪个模版。确认加载后其角色才写入下方列表（无单独应用步骤）；
   与有效集同 code 的角色标记「已修改」，仅有效集有的角色标记「待移除」；
   点「取消编辑」恢复有效集。
5. 点「复用其他项目」：选择来源项目与角色，期望角色以副本合并进草稿，同 code 自动跳过；
   来源项目的角色/模版/角色库保持不变；无权访问的项目不出现在来源列表。
6. 修改项目角色名称、权限或说明后点「确认生效」：期望整组生效、revision 递增，
   名称变化不影响上下游（底层 seat id / code 不变），成员 chip 与授权范围刷新。
   再编辑一个已有角色并选择「创建新角色」：期望 code 自动生成为
   `<CODE>_COPY`（重复时递增），名称为「原名称（副本）」，原角色保持不变；
   保存后副本以「新增」进入草稿。
7. 删除一个仍有成员的角色后确认：期望弹出「成员影响」弹窗列出成员与角色；确认后成员在该角色上的
   指派被清空，成员仍保留在项目中；取消则不生效。
8. 删除一个被项目模版引用的工作流模版所引用的角色：期望弹出「角色不能下线」并列出模版/节点；
   到工作流模版管理停用或编辑该模版后重试可通过。
9. 角色被进行中任务引用时删除并确认：期望任务被标记「需改派」，保留原角色快照与原因；
   已完成任务不受影响。
10. 已启动的工作流实例：角色改名/改权限/删除后，旧实例仍按启动时快照运行，
    新实例使用新角色集；旧实例成员被移出项目后不能再操作。
11. 角色草稿未确认时关闭「项目设置」：期望弹出「放弃角色草稿」确认；
    「继续编辑」保留草稿，「放弃草稿并关闭」丢弃草稿并关闭弹窗。
12. 两个管理员并发确认：后提交者收到 revision 冲突提示，草稿保留。

### P5 成员权限管理

1. 保持项目详情停留在「成员权限」页签，点击「管理成员」。
2. 期望：不离开当前页签；标题保持「成员权限」，成员数量紧挨标题显示在左侧，表格右上角出现「添加成员」，
   且「添加成员」是最右侧按钮；成员行下方直接出现「变更」「移除」操作；点「完成」恢复只读成员列表。
3. 期望：成员区域不出现项目经理、会议 Facilitator 等角色定义列表；
   不出现「项目角色清单」「从模版加载」「复用其他项目」「添加角色」「确认生效」等角色定义操作。
4. 点击「变更」，检查弹窗：
   - 「成员」为只读；
   - 「项目角色」为单选下拉框，只列出当前已生效项目角色和「未分配」；
   - 「授权范围（按项目角色只读汇总）」随勾选联动，不可编辑；
   - 底部有「移除成员 / 取消 / 保存变更」，并提示平台级权限不在此修改。
5. 选择/清空项目角色并保存，期望成员列表角色 chip 与授权范围同步；该角色在任务派发与
   工作流 `role:` 执行人候选中立即可见（可在任务/工作流模块交叉验证）。
6. 添加一位新人员，期望其成为项目成员（工作区成员角色为 member），平台全局角色不变；
   在身份/权限相关页面确认其全局角色未被改动。用人和 AI Teammate 分别检查下拉格式：
   人类为「账号名称（平台角色）」，AI Teammate 为「账号名称·AI（by Owner名称）」；
   同时校验 AI Teammate 的平台角色显示为「未分配」，不随实例 Owner 的平台角色变化。
7. 移除一位成员，期望项目角色指派被释放，成员从项目成员列表消失。
8. 编辑一位人类成员的工作区角色 owner/member/guest 并保存，期望成员列表与成员弹窗立即更新；
   平台角色、全局账号状态和密码不发生变化。
9. 用非平台管理员的工作区负责人账号执行成员添加、工作区角色修改和移除，期望成功；
   直接调用遗留身份成员写接口仍返回 403。
10. 以普通成员身份点击「退出项目」，确认后期望退出成功、本人项目角色被释放、项目从当前列表移除；
    平台账号仍可登录。
11. 项目详情以「工作区：ID [复制图标] · .../相对路径 [复制图标]」单行展示，
    路径展示只保留最后 3 段；两个复制图标分别复制完整 ID 和完整绝对路径。

### P6 历史记录

1. 使用项目负责人或平台管理员打开项目详情，期望出现「历史记录」页签；普通成员不可见。
2. 依次执行项目设置更新、成员添加/项目角色变更/移除、角色保存与确认、模版应用、日报生成。
3. 打开「历史记录」，期望每条操作都会出现，包含操作人、平台角色、时间、摘要与字段变更明细。
4. 检查分类筛选：项目设置、成员权限、项目角色、关联模版、项目日报、账号与权限均能正确过滤。
5. 搜索操作人、成员名称、角色名称和变更字段，期望只保留匹配记录。
6. 平台设置不再提供独立「协作身份」入口；项目成员维护统一从项目管理完成。对历史身份审计数据，
   项目历史仍应合并显示并标记为「账号与权限」。
7. 刷新页面后历史仍存在；同一操作重复执行会追加新记录，不覆盖旧记录。
8. 普通成员直接请求 `/api/collab/projects/history` 返回 403。
9. 给普通成员分配包含 `manage_roles` 的高权限项目角色，再次请求历史记录仍返回 403；
   项目审计访问暂不受项目角色权限控制，后续由平台统一权限体系接管。

### P7 任务清单与工作流

1. 在成员所属项目里创建若干任务与工作流（可用任务/工作流模块，或已有数据）。
2. 回到项目详情的「任务清单」「工作流」页签。
3. 期望：任务按优先级 + 创建时间排序，显示优先级/状态 pill、责任人、截止；点击「详情」
   跳转到任务模块并打开该任务。工作流显示状态 pill 与更新时间，点击「查看流程」跳转并打开实例。

### P8 项目日报

1. 打开「项目日报」页签，期望显示日期区间、关键词、更新日报按钮（仅管理者可见）。
2. 点击「更新日报」。
3. 期望：生成当天快照，包含「今日结论 / 关键进展 / 风险与待确认 / 下一步」，
   事实与项目状态、活跃任务、阻塞工作流一致；再次点击覆盖同一天快照并保留历史。
4. 校验日期区间与关键词过滤只影响展示，不删除历史。

### P9 项目模版维护（平台管理员）

1. 点击页头「项目模版」，进入「项目模版维护」。
2. 「项目模版」面板：新建/编辑/复制/删除模版；基本信息保存；预定义项目角色支持添加与移除；
   预定义工作流模版支持引用与移除（提示本体在工作流 → 工作流模版管理维护）。
3. 「角色库（模版素材）」面板：新建/编辑/删除角色；角色被模版引用时删除返回冲突提示；
   权限勾选决定成员「授权范围」的只读汇总。
4. 用非管理员账号：看不到「项目模版」入口；直接调用模版保存接口返回 403。

### P10 新建项目

1. 点击「新建项目」，填写项目名称，选择项目模版（可选），点击「选择目录」选择本地目录。
2. 提交后期望：左侧栏出现同名项目；项目清单新增该条目；创建者为项目负责人；
   若选了模版，角色清单已按模版物化；磁盘目录内容未被改动。
3. 对已存在成员的项目重复注册同一目录时，非成员账号应被拒绝（已存在成员，无法认领）。

## 3. 回归与清理

- 回归：`corepack pnpm run check`（contract 的 submodule 检查依赖干净的上游子模块；
  若本地子模块有未提交改动会失败，需与项目管理改动区分）。
- 结束后停止本次自行启动的 33119/33121 服务；不要停止或清理正在使用的 33124 环境。
