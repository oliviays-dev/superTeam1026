## 1. 目标

本轮测试回答三个问题：

1. 单点能力是否可用：全局导航、账号、员工目录、任务、工作流、会议、审批和治理入口。
2. 用户小闭环是否走通：任务派发与验收、角色认领、数字员工执行、数字员工入职后交付、会议分身报告、会议/AI 伙伴双模式沟通、审批与治理追溯。
3. 失败是否可见且不越权：缺授权、缺 Runtime、员工暂停、非法审批、执行失败都不能被 UI 显示为成功。

当前边界：

1. `工作台 / 任务管理 / 工作流` 是全局页面；会议模块同时提供会议群聊与 AI 伙伴单聊，中间工作区和右侧沟通栏分别维护当前会话与页签状态。
2. 任务接收方 `DE / 分身` 同时列出平台数字员工与个人 AI Teammate 实例，责任人显示为 `名字（owner）`；`责任人=我` 默认含「我的分身 / 我所在角色」，另有严格的「我（本人）」口径。
3. Digital Employee 无密码登录；任务派发依赖显式工作区授权、启用 Runtime Profile 和 Task Worker 映射。
4. Digital Employee 审批仍等待专用 runtime decision path，浏览器用户不能代签。
5. `by-role` 面板组合仍是预留，不计入失败。
6. 沟通双模式使用会议域承载；AI 单聊是 `kind=ai` 的会议记录，不等同于独立 Home Session，也不等同于会议群聊。

## 3. 单点功能测试

每个用例开始前清空 Console；结束后保存截图、Console 和对象 ID。

### F-01 全局 Shell

所需资料：一个项目、一个 Session。

1. 点击 `工作台`、`任务管理`、`工作流`、`AI Teammates`，确认四者互斥进入主内容区。
2. 点击 `会议`，确认右侧栏独立打开；再次点击关闭。
3. 点击项目树中的 Session，确认回到 Session 内容。
4. 刷新后重复切换。

预期：全局页不覆盖项目树和会议栏；刷新后路由和数据与当前账号一致；`管理` 模式未开放时 disabled；`AI Teammates` 是当前数字员工执行身份的 GUI 入口。

### F-02 账号管理

所需资料：Profile A/B/C。

1. 当前环境从左下角使用 `admin / password-123` 登录；不要依赖共享的 `member` 密码。
2. 打开 Settings > 账号管理，检查当前账号、角色和登录表单。
3. 在 Settings > 协作身份创建 `flow-member / Pluginmax#2026` 和 `flow-viewer / Pluginmax#2026`，再加入测试项目；ID 已存在且密码未知时改用带数字后缀的新账号。

预期：账号切换成功后，任务、员工和工作流重新加载；页面不残留上一账号数据；用户 ID 或密码错误时停留在切换弹窗并显示「用户 ID 或密码不正确」。

### F-03 员工目录与数字员工生命周期

所需资料：左侧 `AI Teammates`、当前测试项目。

1. Settings > 员工 > 目录确认 `Admin`、`Flow Member`、`Flow Viewer` 为启用的真人员工；历史环境中已删除平台账号的 `Workflow Owner / Workflow Member / Workflow Viewer` 投影应显示归档，不应显示启用。
2. 打开 `AI Teammates` > `新建平台 Teammate`，名称填 `Backend Worker`，填写专业角色、基础说明和 SOUL，点击 `保存全局定义`。
3. 点击 `生效`，确认定义状态从 `草稿 / 已失效` 变为 `已生效`。
4. 在 `任务管理` 新建任务并指派给 `Backend Worker`；当前实现会自动开始执行，必要时再补发指令。
5. 回 `AI Teammates` > `定义态管理` > `执行身份`，确认自动生成 Agent Profile、Employee、Runtime Profile 和 Persona。
6. 记录生成的 Employee ID、Agent Profile ID 和 Runtime Profile；暂停、重启各一次；归档留到所有 E2E 完成后验证。

预期：`设置 > Agent` 已下线；执行身份在首次指派并触发任务时自动开通；暂停后新派发被拒绝；旧 `backend-01 / backend-runtime` 不再作为当前环境固定数据。

工作流模板中的 `user:` 引用先按平台账号校验；项目成员关系在启动实例时校验。员工目录只应展示当前平台账号的有效真人投影，账号删除后的历史投影必须归档。

### F-04 任务看板

所需资料：至少一个项目；`admin`（平台管理员）与一个普通成员 Profile；`.tmp/gui-cases/task-progress.txt`。

1. 打开 `任务管理`，确认固定四列：`待处理 / 进行中 / 待验收 / 已完成`；**不存在「已取消」列**。
2. 若环境中已有已取消的历史任务（可由工作流取消产生）：确认它出现在 `已完成` 列、列头计数包含它、卡片带红色「已取消」标记且不可拖拽；打开详情确认除「归档」外均为只读，归档后在归档视图可见，复原后仍回到 `已完成` 列并保留「已取消」标记。没有此类数据时记录为历史数据缺口，不用 API 造数。
3. 项目范围：默认 `仅看已加入`；管理员切到 `平台全量` 后项目下拉列出全部项目；切到 `会议 / 工作流 / AI Teammates` 再回来，范围选择保持一致（跨模块共享）。
4. `新建任务`：填写标题、类型、项目、P1-P3、初始状态、接收人、描述和验收标准；选择 `DE / 分身` 时检查 `完成后自动提交 Review`（默认勾选）。
5. 归属项目：详情页展示项目标题；进入编辑态时项目只读并标注「创建后不可变更」；保存后项目不变；向 `/api/collab/tasks/update` 额外传 `workspaceId` 也不得改项目。
6. 责任人筛选：
   - `我 + 我的分身`（默认）：包含直接指派给我、指派给我的 DE / AI Teammate 实例、我所在角色的任务；分身任务的责任人显示 `名字（owner）`（个人分身与平台型分身都要有归属）。
   - `我（本人）`：只包含直接指派给我的人类任务；分身 / 角色承接的任务不出现，筛选栏给出「另有 N 条由我的分身 / 角色承接」提示。
7. 其余筛选：派出方（全部 / 我）、优先级、来源（全部 / 工作流 / 手动）、关键词和项目下拉；归档视图可往返。
8. 任务详情操作行按责任人类型与状态检查：
   - 人类任务：开始 / 提交验收 / 通过 / 退回 / 催办（催办只在“派出方是我 + 任务未结 + 责任人是人类”时出现）。
   - Agent 任务：`打开会话` 可用；**没有 `人工回复`、`派我的分身执行`、`重置会话` 入口**。
   - 已归档：操作只读并给出提示；已取消：除「归档」外只读并给出提示。
9. 详情页信息：归属项目、责任人（含 owner）、创建人/时间、优先级/到期、完成后自动提交 Review，与看板卡片一致；发送一条带附件的指令，确认附件显示名称、大小和类型信息。
10. 只读外部 Runtime 产出：让 Agent 生成具名 Markdown 文档但不写工作区，确认运行结果中的文件名和正文被登记到右侧「产出文档」，文件可下载，产出者显示 Agent 而不是验收人。
11. 关键共识增量：在评论区勾选「关键共识」并发送一条不 @ Agent 的评论；确认评论出现「关键共识」标签，且不会立即触发 Agent 或改变任务状态。随后通过上方执行反馈发送一条指令，确认该关键共识进入本次 Agent 上下文；再次追加普通指令时，持久会话确认已投递共识不重复注入，无状态 Runtime 确认当前有效共识会完整重放并在本轮 Receipt 中继续留痕。
12. 右侧执行信息：`AI执行记录` 位于 `关联事项` 下方，默认选中最新一轮；轮次使用紧凑下拉框，收起时触发器显示“轮次 · AI 伙伴 · 状态”，右侧同步显示当前轮的指令发送时间，其正下方展示当前轮 `本轮指令` 明细卡，指令默认三行，可展开/收起全文；展开下拉框后固定明细卡隐藏，轮次按最新在前排列，每轮显示轮次、AI 伙伴、状态、指令发送时间和 `本轮指令`，点击轮次卡片任意非“展开完整指令”区域均可选中该轮，且展开指令不会误触发选轮。指令发送时间使用 Agent Run 的实际创建/投递时间（`agent.dispatch` 时刻），即指令真正发送给 Agent 的时间，而不是用户录入消息或改派事件的时间。无显式触发消息时，使用相邻改派记录或任务初始指令作为轮次说明。AI 伙伴信息已在轮次触发器和运行信息标题中展示，内部不再重复展示 `AI伙伴` 区块；切换后，`产出物 / 执行过程 / 运行信息` 三个二级区同步切换。Run 详情返回前显示“正在读取运行信息”；旧轮次仍有 Run 记录但未持久化运行元数据时，应展示按当前 Agent 配置回填的 Provider、Runtime、版本/认证和沙箱，并明确标注“历史配置回填”；若关联 Run 已不存在，则显示“该轮未记录运行元数据”及原因说明，不能只显示空白。产出物必须按 `runId` 归属到对应轮次。
13. 混合执行归属回归：同一任务依次经历“内置 Runtime → 改派人类 → 外部 WorkBuddy → 改派人类 → 另一个 CodeBuddy 外部 Runtime”。确认人类改派记录保留在任务动态/执行历史，轮次下拉框中的指令与各轮一致；切换轮次时只展示该轮 AI 伙伴、产出物、执行过程和运行信息，不串轮次。

预期：四列固定且无「已取消」列；已取消历史在 `已完成` 列中可区分且可归档/复原；项目范围与责任人口径的切换结果与说明一致；归属项目创建后不可变更；操作行与任务类型匹配，不出现已下线或隐藏的按钮；无接收方时发送按钮 disabled；只读 Runtime 的具名文档进入对应轮次的 `AI执行记录 > 产出物`，不会在其它轮次串显；轮次下拉框位于 `AI执行记录` 顶部，触发器收起态显示轮次、AI 伙伴、状态和指令发送时间，当前轮指令明细卡固定在其下方，展开下拉框后显示各轮指令并隐藏固定明细卡，`产出物 / 执行过程 / 运行信息` 三个二级区随轮次整体联动，不再重复展示 AI伙伴区块。

### F-05 真人任务执行与验收

所需资料：Profile A/B。

1. A 给 B 派发任务，验收标准写两条。
2. B 在 `责任人 > 我（本人）` 打开任务，点击 `开始`。
3. B 发送执行消息并发起 `提交验收`。
4. A 点击 `退回`，在必填弹窗中输入退回说明；不填写时确认按钮保持 disabled。B 回复后重新提交。
5. A 在 B 的任务详情点击 `催办`（仅人类任务可见）。
6. B 打开 `工作台` 查看个人简报；同时 A 打开任务动态。
7. A 点击 `通过`。

预期：状态按 `待处理 → 进行中 → 待验收 → 进行中 → 待验收 → 已完成` 变化；只有通过后进度为 100%；退回说明为必填并写入任务执行历史，直接调用接口传入空说明必须返回 400；事件保留操作人、时间和动作；未勾选任何验收项时提交被服务端拒绝，任务保持 `进行中` 且不会自动代勾第一项；勾选至少一项后允许进入 `待验收`。催办后任务动态出现 `nudge` 事件，B 的个人简报出现该任务且标签为「被催办」、原因写明「被 A 催办」；Agent 承接的任务不显示催办入口，直接调接口催办应返回 409「只有指派给人类的任务可以催办」。

### F-07 数字员工任务执行

所需资料：F-03 已完成；`.tmp/gui-cases/task-progress.txt`。

预期：AI 消息依次显示 `queued / running / succeeded` 或明确失败；任务由 `待处理` 进入 `进行中`；执行身份在首次指派并触发任务时自动生成；执行期间责任人显示 `Agent（owner）`；自动提交 Review 后责任人交回实例 owner（A），任务进入 A 的待验收与工作台；执行历史仍保留 Agent 产出，且「打开会话」继续可追溯该 Agent 会话；失败原因可见且不会假成功；不创建左侧 Home Session。

#### 3.1.3 测试前置

1. 使用 Profile A `admin / password-123`；准备一个可用项目 `<WS_ID>` 和一个 active AI Teammate `GUI 沟通伙伴`。

#### G-01 统一沟通列表与筛选

1. 创建一个会议和一个 AI 单聊，返回会议页。
2. 检查两者出现在同一左侧列表，AI 行有 `AI` 标记和 owner，会议行有状态/项目。
3. 切换「仅看已加入 / 平台全量」，再分别切换项目和状态。
4. 在搜索框输入 AI 名称和会议标题。

预期：两种会话均可检索和筛选；范围切换不会清空另一个面板的当前选中；AI 行不显示会议编号或纪要状态。

#### G-02 AI 单聊创建与复用

1. 点击顶部「AI 对话」，选择 `GUI 沟通伙伴`，创建。
2. 记录 `meetingId`、`kind=ai`、`teammateInstanceId` 和参与者。
3. 返回列表，再次点击同一 AI 发起对话。

预期：首次返回 201，第二次复用原会话；参与者为当前人类 + 指定 AI；不得创建两个同名 active AI 线程。

#### G-03 AI 消息、任务与 session

1. 在 AI 单聊发送一条无需 @ 的指令。
2. 检查聊天 transcript、会议侧 AI 参与方、任务时间线和左侧 session。
3. 等待 Agent 回复，检查回复是否进入 AI 单聊而不是会议群聊。

预期：消息实际落库；生成或复用 `(meetingId, teammateInstanceId)` 对应任务；AI 回复以 `senderKind=ai`/agent 身份回写；不出现“已接收指令”占位长期停留；失败时有明确错误。

#### G-04 中间区与右侧栏独立操作

1. 中间选中会议 A，右侧栏选中 AI 单聊 B。
2. 中间切换到「设置」，右侧保持「对话」；在两侧各输入不同草稿。
3. 在右侧切换会议 C，再切回 AI B；中间仍停留在会议 A/设置。

预期：两侧 `meetingId`、页签、草稿均独立；任何一侧刷新不得重置另一侧；AI 侧始终无会议页签。

#### G-05 右侧切换器默认筛选和弱链接

1. 打开右侧栏切换器，不清空历史数据。
2. 检查默认可见项全部为进行中，归档和已结束项不出现。
3. 点击底部「查看全部」，确认全部会话展开；再次点击「仅看进行中」返回。

预期：默认无已归档；「查看全部」是文本链接而不是主按钮；切换后当前选中和中间区不被重置。

#### G-06 会议设置数据与功能完整性

1. 中间选中会议，进入设置，检查关联项目、状态、名称、议程、Facilitator、成员。
2. 修改名称和议程并保存，刷新后回读。
3. 切换 Facilitator，邀请并移除 active 成员；确认离会成员不显示。
4. 检查成员顺序为人类 → Facilitator → AI 伙伴。

预期：设置数据属于当前会议；保存回读一致；Facilitator checkbox 与成员列表同步；离会成员仍保留历史但不可见；重新邀请复用 participant id。

#### G-07 纪要更新、下载与滚动

1. 打开会议纪要，点击更新；已有内容时检查覆盖确认，确认后观察生成状态和最终内容。
2. 点击下载，检查 `.md` 文件名、UTF-8 正文和标题。
3. 分别追加系统消息、人类消息、AI 消息，将滚动条上移后发送。
4. 进入设置再切回对话。

预期：更新调用无 `action is not a function`；下载文件名为 `会议名称-会议纪要-vN.md`；每次追加都自动滚到底部；切回对话也自动到最新。

#### G-08 默认项目与无项目会议

1. 新建会议时选择「默认项目」，或调用创建接口省略 workspaceId。
2. 检查列表项目归属和筛选分组。
3. 检查项目名在会议详情/设置中显示为“默认项目”。

预期：记录持久化 workspaceId=`system.default`；不要求真实 workspace 注册；普通用户可查看和操作；默认项目选项包含 system owner 提示。

#### G-09 已离会成员与 Facilitator 反馈

1. 移除一个 AI 成员，检查成员列表立即消失。
2. 重新邀请同一 AI，检查参与者 id 复用且状态恢复 active。
3. 关闭并重新开启 Facilitator，检查系统消息顺序。

预期：离会记录不展示；重新邀请可成功且不出现重复成员；Facilitator 每次重入追加“会议 Facilitator 已加入会议。”；移除消息保留在 transcript。

#### G-10 响应式与页面高度

2. 检查顶部范围、左侧项目/状态下拉、搜索、中心标题行、页签和 composer。
