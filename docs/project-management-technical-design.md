# 项目管理模块技术设计（dsh-collab-project）

参照 `docs/demos/task-management-demo.html` 的「项目管理」设计实现。本文记录落地边界：
哪些沿用既有模块、哪些由本插件新增，以及当前版本的已知取舍。

> 2026-10-17 方向调整：项目成员与项目角色的长期主体将从账号/数字员工收敛为 Principal。当前 `ctx.collabEmployee` 和 `employeeId` 仅作为迁移期兼容；后续项目成员候选统一为 Human Principal 与 AI Principal。新方案见 `docs/platform-principal-rbac-design.md`。

## 1. 范围

模块覆盖 demo 中的这份清单：

- 项目清单（搜索、状态、Owner、进度、健康度）
- 项目详情六个页签：成员权限、产出物、任务清单、工作流、项目日报、历史记录
- 成员权限管理（增减成员、维护成员的项目角色）
- 项目模版维护（项目模版 + 项目角色库两个面板）
- 新建项目

demo 中已隐藏的「用户权限管理」（access）页不在本次范围内。

## 2. 关键决策

| 决策                 | 选择                                                                | 原因                                                                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 项目实体             | **项目 = DSH 工作区**                                               | 任务、工作流、会议、Teammate、工作台关注都已按 `workspaceId` 归属；再建一套项目实体需要改五处关联                                                                                                           |
| 项目扩展信息         | 新存储域 `collab_project`，主键 `workspaceId`                       | 工作区注册表拥有标题与目录，项目管理只补充编码、负责人、状态、健康度、进度、起止日期、说明、日报                                                                                                            |
| 成员的项目角色       | 写入 `dsh-collab-roles` 的席位指派（`ctx.collabAssignment`）        | 任务派发与工作流 `role:` 执行人已经在消费它，避免第二份真相                                                                                                                                                 |
| 项目角色定义         | **每个项目持有一份 `projectRoles` 副本**                            | 模版只负责初始化；项目内可自由增删改，互不影响，也不会反向修改模版或全局角色库                                                                                                                              |
| 角色库 / 项目模版    | 由本插件拥有（`collab_project.roles` / `collab_project.templates`） | 角色库是「模版素材」；项目模版按类型预置角色清单与工作流模版引用；工作流模版本体仍由工作流模块维护                                                                                                          |
| 平台级账号与角色权限 | **项目管理内只读**                                                  | 成员弹窗在平台用户选项中只读展示全局平台角色；添加成员只写工作区成员关系（默认 `member`），不改 `collab_team.users` 的全局角色，也不调用 `/api/collab/team/users/*`                                         |
| 工作区成员角色       | 平台管理员或工作区负责人可维护 `owner` / `member` / `guest`         | 属于工作区成员关系，不是平台账号的全局角色；不修改账号、密码、启停用状态或平台角色                                                                                                                          |
| 项目日报             | 由项目状态 + 任务/工作流快照确定性生成，按日期覆盖保存              | demo 的「更新日报」就是模板化聚合；不引入模型依赖，后续可替换为 Agent 生成                                                                                                                                  |
| 项目历史记录         | 独立、只追加的 `collab_project.audit`，并合并身份审计               | 项目设置、角色、成员项目角色、模版应用、日报与平台侧成员关系变更统一按 `workspaceId` 审计，不随当前配置覆盖                                                                                                 |
| 项目阶段性产出物     | 项目级独立对象，记录阶段、主题、产出时间、产出者与来源引用          | 文件是项目资产，任务 / 工作流 / 会议是来源；节点交付物继续承担流程门禁，不复制成第二份交付事实                                                                                                                |
| 新建项目             | 选择一个已存在的本地目录并注册为工作区                              | DSH 工作区是目录的持久记录，模块只注册目录、不创建/改动磁盘内容；创建者成为项目负责人与成员                                                                                                                 |
| `projects` 路由归属  | 由本插件独占                                                        | 工作台曾注册过一个只读项目列表页（只有计数 + 关注、项目名不可点击）。两个页面会同时挂在 `pluginmax.global` 列表里，因此工作台侧已移除该页面，只保留 `/api/collab/workbench/projects` 聚合接口与项目关注按钮 |

## 3. 数据模型

存储域 `collab_project`（version 1）：

| 表          | 键                  | 内容                                                                                                                                                                                                          |
| ----------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `projects`  | `workspaceId`       | 项目扩展信息：`code` / `ownerId` / `ownerName` / `status` / `health` / `progress` / `startDate` / `targetDate` / `description` / `templateId` / `projectRoles`（项目自己的角色定义副本） / `rolesInitialized` |
| `roles`     | 角色 id             | 模版素材角色库：`name` / `code` / `category` / `description` / `permissions`（`read`、`write`、`approve`、`manage_members`、`manage_roles`）                                                                  |
| `templates` | 模版 id             | 项目模版：`name` / `code` / `type` / `status` / `description` / `roleIds` / `workflowTemplateIds`                                                                                                             |
| `reports`   | `workspaceId::date` | 项目日报快照：`date` / `generatedAt` / `generatedBy` / `content`（Markdown）                                                                                                                                  |
| `audit`     | 事件 id             | 项目审计事件：`workspaceId` / `at` / 操作人快照 / `category` / `action` / `target` / `summary` / `detail`；只追加不更新                                                                                       |
| `artifacts` | 产出物 id           | 阶段性产出物：`workspaceId` / `title` / `format` / `stage` / `theme` / `producedAt` / `producerPrincipalId` / `sourceRef` / `summary` / `status`                                                           |

首次启动写入与 demo 一致的 13 个项目角色与 3 个项目模版（插件、员工平台、供应链采购）。
内置模版的 `workflowTemplateIds` 留空：工作流模版本体由 `dsh-collab-workflow` 拥有，不伪造引用。

项目记录缺失时自动建档：默认 Owner 取工作区的 `owner` 成员，状态「进行中」、健康度「健康」、进度 0；
读路径（清单 / 详情 / 日报）也会兜底建档，保证清单里不会出现「未编号」。

项目编号（`code`）在**项目创建时**生效：插件订阅宿主的 `workspaceController.follow()` 变更流，
`baseline` 帧为既有工作区补齐 `PRJ` + 6 位数字（`PRJ000001` 起递增），`upsert` 帧在项目注册那一刻
分配编号；经 `/api/collab/projects/create` 创建的项目在同一个请求里落编号。编号一经分配不再变化，
并兼容历史 `PRJ-001` 形式（取两套写法的最大数字继续递增）。

## 4. 与既有模块的集成

| 能力                         | 来源                                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| 项目清单、标题、目录         | `ctx.workspaceRegistry`（`create` / `get` / `list` / `setTitle`）                       |
| 工作区成员、平台角色（只读） | `ctx.collabTeam`（`members` / `users` / `addMember` / `removeMember` / `audit`）        |
| 项目角色席位与指派           | `ctx.collabAssignment`（`config` / `seats` / `materialize` / `assign` / `release`）     |
| AI 成员目录与名称            | `ctx.collabTeammateRuntime.assignable`；`ctx.collabEmployee` 仅作 Principal 迁移期兼容  |
| 任务清单与统计               | `ctx.collabTasks.list(workspaceId)`                                                     |
| 工作流实例与模版引用候选     | `ctx.collabWorkflow.instances` / `sharedDefinitions`                                    |
| 项目关注                     | 工作台 `/api/collab/workbench/follows/toggle`（`type=project`, `targetId=workspaceId`） |
| 任务 / 工作流深链            | `window.__pluginmaxPendingTask` + `pluginmax:collab-navigate`（与工作台一致）           |

**角色副本语义**：

- 项目创建时把模版引用的角色定义**复制**进 `project.projectRoles`，再同步为 roles 插件的席位；
- 项目内编辑采用「草稿 → 确认生效」：列表展示有效集 + 草稿差异，确认时整组覆盖，
  不再有单条增量生效；`rolesRevision` 防止并发覆盖；
- 编辑已有角色时可选「调整原有角色」或「创建新角色」；新角色由系统生成新的 code，
  原角色及其成员指派保持不变；
- 「从模版加载」与「复用其他项目」是两个平行草稿入口：前者替换草稿，后者按 code 合并去重；
- 删除角色前检查成员影响（二次确认后清空对应指派）、已加载工作流模版引用（被引用则禁止下线）、
  进行中任务（允许删除并标记「需改派」）；
- 已启动工作流实例在启动时保存角色快照，后续角色编辑/删除不影响旧实例；新实例使用新角色集；
- `dsh-collab-roles` 默认补齐的「会议 Facilitator」按系统席位只读展示，不计入项目自定义角色。

完整规则与边缘 case 见 [project-role-draft-confirm-design.md](project-role-draft-confirm-design.md)。

读路径对「未物化」是降级而不是报错：项目清单、详情与成员移除遇到尚未物化角色的工作区时，
按「该项目暂无项目角色」处理（`roles: []`、成员只统计真人），避免整个项目页因 `seats()`
抛 `not_found` 而 500。

## 5. 浏览器接口

全部为同源 + Bearer 保护，前缀 `/api/collab/projects`。

| 方法 | 路径                                    | 权限                   | 说明                                               |
| ---- | --------------------------------------- | ---------------------- | -------------------------------------------------- |
| GET  | `/`                                     | 登录用户               | 项目清单；管理员看全部，其他用户只看已加入项目     |
| GET  | `/detail`                               | 项目成员或平台管理员   | 项目详情、成员、项目角色、目录候选、任务、工作流   |
| POST | `/create`                               | 登录用户               | 注册目录为项目；空成员项目由创建者成为 Owner       |
| POST | `/update`                               | 项目负责人或平台管理员 | 更新项目扩展信息（负责人须是项目成员）             |
| GET  | `/templates`                            | 登录用户               | 项目模版、角色库、可引用的工作流模版               |
| POST | `/templates/save` / `/templates/remove` | 平台管理员             | 项目模版维护                                       |
| POST | `/roles/confirm`                        | 项目负责人或平台管理员 | 草稿整组确认生效（成员影响 / 工作流模版校验）      |
| POST | `/templates/apply`                      | 项目负责人或平台管理员 | 兼容接口；新 UI 不再使用                           |
| POST | `/roles/save` / `/roles/remove`         | 平台管理员             | 模版素材角色库维护；被模版引用的角色不可删除       |
| POST | `/role/save` / `/role/remove`           | 项目负责人或平台管理员 | 兼容接口；新 UI 不再使用                           |
| GET  | `/role-sources`                         | 项目成员或平台管理员   | 列出当前用户可访问、且已有角色的其他项目           |
| POST | `/role/import`                          | 目标项目负责人或管理员 | 兼容接口；新 UI 在草稿内合并                       |
| POST | `/members/save` / `/members/remove`     | 项目负责人或平台管理员 | 增减成员、同步项目角色指派                         |
| POST | `/leave`                                | 当前项目成员           | 主动退出项目（工作区），释放本人项目角色           |
| GET  | `/reports`                              | 项目成员或平台管理员   | 项目日报列表                                       |
| POST | `/reports/generate`                     | 项目负责人或平台管理员 | 生成/覆盖当天日报                                  |
| GET  | `/history`                              | 项目负责人或平台管理员 | 项目审计时间线；合并账号与权限中与该项目相关的事件 |

权限口径：平台级管理员（`user.role = admin`）拥有全部项目权限；项目负责人由工作区成员角色
`owner` 判定。成员弹窗中的平台角色只读展示，写接口不会修改平台账号与平台角色。

历史记录暂不接项目自定义角色权限：即使成员持有 `manage_roles` 等高权限项目角色，也不会因此
获得审计记录访问权。当前沿用平台管理员 / 工作区负责人的既有管理口径，后续由平台统一权限体系
接管审计访问控制。

工作区成员角色编辑只修改 `collab_team.workspace_members` 中的 `owner/member/guest`，不修改
`collab_team.users.role`、账号状态、密码或登录会话，因此不违反“项目管理不编辑平台级账号/角色权限”。
退出项目同样是自服务成员关系操作。遗留身份 API 仍保持平台管理员权限；只有项目路由通过显式
`allowWorkspaceOwner` 能力允许工作区负责人管理成员。

## 6. 客户端页面

`client/index.js` 注册到 `pluginmax.global`（id `pluginmax-project`，order 32），
左侧导航在「工作流」之后新增「项目管理」入口（`dsh-collab-shell`）。

- 目录列：搜索 + 项目清单（首字母标记、编码、Owner、状态）
- 详情：标题行（状态/健康度 pill）、编码/Owner/起止日期/进度、说明、工作区 ID/路径及复制图标、
  关注、项目设置、退出项目、三项事实卡、五个页签（历史记录仅项目负责人/平台管理员可见）
- 项目设置：`基础信息` / `项目角色` 两个页签；基础信息维护项目元数据，项目角色定义在同一
  编辑上下文中完成草稿与确认
- 成员权限管理：在成员权限页签内切换管理模式；标题保持「成员权限」，成员数量紧跟标题，
  「添加成员」作为表格右上角最右侧按钮，行操作变为「变更 / 移除」，点「完成」恢复只读列表
- 产出物：按项目阶段分组，组内按时间倒序形成时间轴；顶部提供阶段、主题、日期范围与关键词筛选；
  每条产出物显示文件、产出者、时间与来源，来源可追溯至任务卡、工作流实例或会议
- 成员信息：展示工作区角色与加入时间；成员弹窗可编辑工作区角色和项目角色
- 项目角色清单（项目设置 → 项目角色）：从模版加载 / 复用其他项目 / 添加角色；行状态区分
  已生效 / 新增 / 已修改 / 待移除；底部取消编辑 / 确认生效
- 关闭存在未确认角色草稿的编辑弹窗时，二次确认是否放弃；确认时按需弹出成员影响、工作流模版
  阻塞、revision 冲突提示；成员弹窗的平台角色仍只读
- 项目模版维护：项目模版面板（基本信息/预定义项目角色/预定义工作流模版）与项目角色库面板
- 历史记录：按项目设置 / 成员权限 / 项目角色 / 关联模版 / 项目日报 / 账号与权限筛选和搜索；
  事件包含操作人、时间、摘要和字段变更明细
- 成员弹窗：平台用户下拉显示平台角色；AI Teammate 不再继承实例 Owner 的平台角色，
  下拉显示为「账号名称·AI（by Owner名称）」，成员详情中的平台角色显示「未分配」；
  人类用户显示为「账号名称（平台角色）」；项目角色改为单选下拉框。后续接入独立平台角色授权时，
  Owner 仍只表示业务负责人，不作为授权来源
- 模态：项目设置、编辑成员、新建项目（名称 + 可选模版 + 选择目录）

样式与控件沿用任务 / AI Teammate 模块的 DSW 变量与 6–7px 圆角、按钮/输入高度口径。

## 7. 未来层级扩展

当前严格保持 `project = workspace`（1:1），项目主键仍为 `workspaceId`。未来支持子工作区 / 子项目时，
新增父级引用与树形路径字段，不改变现有项目编号和审计身份；父项目仍保留自己的项目记录，子项目通过
`parentWorkspaceId` / `projectPath` 等字段挂接，避免一次性迁移现有数据。

## 9. 已知边界与后续迭代

1. **日报内容**：当前是确定性聚合，署名「项目 AI」。后续可接入 Agent 生成（异步 + 失败回退），
   接口与快照结构不变。
2. **授权范围**：demo 是自由文本，这里改为角色权限（查看/编辑/审批/成员管理/角色管理）的只读汇总；
   角色权限在项目角色库中维护。
3. **项目改名**：项目名即工作区标题，仍由左侧栏的工作区入口维护；详情弹窗中名称只读。
4. **平台角色展示**：`平台管理员 / 平台负责人 / 平台成员 / 平台访客` 是只读标签，
   不代表可在此调整平台权限。
5. **项目模版与角色库写权限**：当前仅平台管理员可维护；如需允许项目负责人自建模版，需要产品确认。
6. **Teammate 候选范围**：沿用任务模块的 `assignable(actor)` 口径，即当前操作者可指派的实例；
   跨 owner 的实例需要更高权限或产品补充规则。

## 10. 项目阶段性产出物方案

### 10.1 对象定义

阶段性产出物是项目资产，不等同于工作流节点交付物。节点交付物回答“流程是否满足门禁”，项目产出物回答
“项目在某个阶段沉淀了什么可复用结果”。两者通过来源引用建立关系，不复制文件事实。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定产出物 ID，不随文件改名变化 |
| `workspaceId` | 所属项目 / 工作区 |
| `title` / `format` | 文件名与文件格式 |
| `stage` | 项目阶段，按项目配置排序 |
| `theme` | 主题分类，用于横向检索 |
| `producedAt` | 产出时间 |
| `producerPrincipalId` | 产出者，可为真人或 AI Principal |
| `sourceRef` | 来源类型与 ID：任务卡 / 工作流实例或节点 / 会议或消息 / 人工上传 |
| `summary` | 面向项目概览的摘要，不替代文件正文 |
| `status` | 有效 / 待确认 / 已归档，后续可扩展版本与替换关系 |

### 10.2 组织与交互

- 项目详情新增「产出物」实例页签，与项目设置中的定义信息分离；
- 默认按阶段分组，组内按产出时间倒序；时间轴服务于“何时产出了什么”，阶段服务于“项目走到哪一步”；
- 筛选条件为阶段、主题、日期范围、关键词，组合过滤即时生效；
- 文件名打开只读详情；来源按钮承担追溯，不把“打开文件”和“打开来源”混成同一个动作；
- 任务来源跳转任务详情，工作流来源跳转实例详情，会议来源在当前页面并行打开沟通侧栏；
- AI 产出者使用 agent 色和 AI 标签，真人与 AI 共用同一头像与身份槽位。
