# 平台账号、角色权限与项目管理 GUI 测试方案

> 适用范围：DSH Pluginmax 当前版本  
> 测试类型：GUI 功能、权限、上下游集成与回归  
> 覆盖模块：账号管理、工作区角色席位、项目设置、项目成员、项目角色、项目模版、项目审计、
> 任务管理、工作流、AI Teammate、工作台  
> 测试日期：2026-10-17

> 2026-10-17 目标调整：Phase 1.5 已把当前「身份与权限」收敛为「账号与权限」，并移除企业员工页签。本测试方案中的账号、角色、项目成员和项目角色链路继续有效；所有涉及企业员工目录或数字员工独立入口的断言，应改为迁移期兼容测试，不再作为目标产品验收项。新方案见 `docs/platform-principal-rbac-design.md`。

## 1. 测试目标

本方案验证以下三层权限模型及其上下游链路：

1. **平台账号与全局角色**：`admin / owner / member / guest`。
2. **工作区成员角色**：`owner / member / guest`，属于项目成员关系。
3. **项目自定义角色**：每个项目独立持有，权限包括查看、编辑、审批、成员管理、角色管理。

重点验证：

- 平台账号和全局角色只能在「平台设置 → 账号与权限」维护。
- 项目设置可维护工作区成员角色和项目自定义角色，但不能修改平台账号、密码、启停用或全局角色。
- 项目角色不影响平台账号权限；项目角色也不能获得项目审计记录访问权。
- 项目成员、项目角色、模版、任务、工作流和审计之间的数据联动正确。
- 已启动工作流实例不受后续项目角色变更影响。
- 非成员、无权限用户和无效 Token 的 GUI 拒绝路径完整。

## 2. 当前产品边界

| 能力                                 | 当前入口                         | 说明                             |
| ------------------------------------ | -------------------------------- | -------------------------------- |
| 平台账号创建、编辑、停用、启用       | 平台设置 → 账号与权限 → 登录账号 | 仅平台管理员可管理               |
| 平台全局角色                         | 平台设置 → 账号与权限 → 登录账号 | `admin / owner / member / guest` |
| 工作区成员添加、移除、工作区角色修改 | 项目管理 → 成员权限              | 平台管理员或工作区负责人可操作   |
| 退出项目                             | 项目详情 → 退出项目              | 当前成员自助操作                 |
| 项目自定义角色                       | 项目设置 → 项目角色              | 每个项目持有角色副本             |
| 工作区类型与席位                     | 平台设置 → 账号与权限 → 角色     | 用于工作区角色模板、认领与释放   |
| 项目审计                             | 项目详情 → 历史记录              | 平台管理员或工作区负责人可查看   |
| `平台设置 → 协作身份`                | 已下线                           | 保留身份服务，不提供页面入口     |

### 2.1 权限层级对照

| 层级                 | 示例                       | 存储                            | 项目内可编辑                     |
| -------------------- | -------------------------- | ------------------------------- | -------------------------------- |
| 平台账号             | `qa-member`、密码、启停用  | `collab_team.users`             | 否                               |
| 平台全局角色         | 平台管理员 / 平台成员      | `collab_team.users.role`        | 否                               |
| 工作区成员角色       | 工作区负责人 / 成员 / 访客 | `collab_team.workspace_members` | 是                               |
| 项目自定义角色       | 项目经理 / Builder         | 项目 `projectRoles` + 角色席位  | 是                               |
| 工作区类型席位       | 主持人 / Builder           | 角色插件                        | 是，平台设置 → 账号与权限 → 角色 |
| AI Teammate 平台角色 | 未分配，不从 Owner 派生    | 暂无平台角色授权记录            | 否，当前只读                     |

## 5. 测试用例

### 5.1 平台账号管理

#### ACCT-01 首次管理员初始化

**优先级**：P0  
**前置**：全新环境，未初始化账号。  
**步骤**：

1. Profile A 打开完整 launch URL。
2. 打开「平台设置 → 账号与权限 → 登录账号」。
3. 输入 `qa-admin`、`Qa Admin`、`Qa-admin-2026`。
4. 点击「创建管理员」。
5. 刷新页面。

**预期**：

- 创建成功，页面显示当前账号 `qa-admin`、`Qa Admin`、`admin`。
- 刷新后保持登录态。
- 「账号」管理面板出现。
- 设置侧边栏只出现「账号与权限」，其页签包含「登录账号 / 角色 / 审计」。

#### ACCT-02 创建测试账号

**优先级**：P0  
**前置**：ACCT-01 完成。  
**步骤**：

1. Profile A 在「账号与权限 → 登录账号」依次创建：
   - `qa-owner` / `QA Owner` / `member`
   - `qa-member` / `QA Member` / `member`
   - `qa-guest` / `QA Guest` / `guest`
   - `qa-outsider` / `QA Outsider` / `member`
2. 每次创建后检查表格。

**预期**：

- 四个账号均出现在账号表，全局角色正确。
- 新账号只创建全局身份，不自动成为任何项目成员。
- 提示引导用户前往项目管理添加项目成员。

#### ACCT-03 编辑账号名称和全局角色

**优先级**：P0  
**前置**：ACCT-02 完成。  
**步骤**：

1. Profile A 将 `qa-guest` 名称改为 `QA Guest Updated`。
2. 将 `qa-outsider` 全局角色从 `member` 改为 `guest`，再改回 `member`。
3. 在 Profile E 刷新页面。

**预期**：

- 账号表即时更新。
- Profile E 的显示名称和全局角色刷新后同步。
- 项目成员列表中的平台角色同步更新。
- 工作区成员角色和项目角色不被修改。

#### ACCT-04 最后管理员保护

**优先级**：P0  
**前置**：环境中只有一个 admin。  
**步骤**：

1. Profile A 尝试把自己的全局角色改为 `member`。
2. 尝试停用 `qa-admin`。

**预期**：

- 两次操作均被拒绝。
- 页面显示「最后一个管理员不能被降级或停用」。
- `qa-admin` 仍可继续使用平台管理功能。

#### ACCT-05 停用账号与会话吊销

**优先级**：P0  
**前置**：Profile C 已登录 `qa-member`。  
**步骤**：

1. Profile A 在「账号与权限 → 登录账号」停用 `qa-member`。
2. Profile C 刷新页面并尝试访问项目、任务和工作流。
3. Profile A 重新启用 `qa-member`。
4. Profile C 重新登录。

**预期**：

- 停用后 Profile C 的旧会话失效，受保护页面显示登录或未授权状态。
- 项目成员关系与历史审计保留。
- 启用后可重新登录，项目关系恢复可见。

#### ACCT-06 修改密码

**优先级**：P1  
**步骤**：

1. Profile B 在「账号与权限 → 登录账号」中修改密码。
2. 退出并使用旧密码登录。
3. 使用新密码登录。

**预期**：旧密码失败，新密码成功；其他账号会话不受影响。

#### ACCT-07 非管理员登录账号边界

**优先级**：P0  
**步骤**：

1. Profile B/C/D 分别打开「账号与权限 → 登录账号」。
2. 检查账号列表和用户编辑入口。

**预期**：

- 非管理员只能查看并修改自己的密码。
- 看不到全局账号列表、创建账号、全局角色编辑、停用/启用操作。
- 直接调用用户写接口返回 403。

#### ACCT-08 已下线协作身份入口

**优先级**：P0  
**步骤**：打开平台设置侧边栏和已保存书签/历史入口。

**预期**：

- 不出现独立的「账号管理」「员工」「角色」设置页签。
- 不出现工作区成员、审计时间线旧页面。
- 「账号与权限 → 登录账号」正常，项目管理成员维护正常。

### 5.2 工作区角色与角色席位

#### ROLE-01 添加工作区成员并设置角色

**优先级**：P0  
**前置**：两个项目已创建。  
**步骤**：

1. Profile A 打开 `QA-Alpha` → 成员权限 → 管理成员 → 添加成员。
2. 添加 `qa-owner`，工作区角色为「负责人」，项目角色为「项目经理」。
3. 添加 `qa-member`，工作区角色为「成员」，项目角色为「Builder」。
4. 添加 `qa-guest`，工作区角色为「访客」，项目角色为「Reviewer」。

**预期**：

- 成员表显示头像、加入时间、工作区角色、平台角色、项目角色、授权范围。
- `qa-owner` 全局平台角色仍为「平台成员」，不变成平台管理员。
- 成员总数正确，AI 与人类数量拆分正确。

#### ROLE-02 工作区负责人管理成员

**优先级**：P0  
**前置**：Profile B 是 Alpha 工作区负责人，非平台管理员。  
**步骤**：

1. Profile B 添加 `qa-outsider` 为工作区成员。
2. 修改其工作区角色为 guest。
3. 移除 `qa-outsider`。

**预期**：三次操作成功；平台全局角色不变；审计出现对应记录。

#### ROLE-03 普通成员不能管理成员

**优先级**：P0  
**前置**：Profile C 是 Alpha 普通成员。  
**步骤**：

1. 打开成员权限页。
2. 检查管理入口。
3. 尝试直接调用成员保存/移除接口。

**预期**：GUI 不显示管理入口；接口返回 403；无权限提示可理解。

#### ROLE-04 访客与未加入账号

**优先级**：P0  
**步骤**：

1. Profile D 打开 Alpha。
2. Profile E 打开 Alpha。
3. 检查项目列表、详情和成员管理。

**预期**：

- 访客按现有工作区策略只能查看。
- 未加入的用户列表中看不到 Alpha，直接访问详情返回 403。
- 不泄露项目成员、任务、工作流和审计数据。

#### ROLE-05 工作区角色变更不修改平台角色

**优先级**：P0  
**步骤**：

1. Profile A 将 `qa-member` 工作区角色从 member 改为 guest，再改回 member。
2. 在「账号与权限 → 登录账号」查看 `qa-member`。

**预期**：工作区角色变化；全局角色仍为 member；账号状态和密码不变。

#### ROLE-06 退出项目

**优先级**：P0  
**前置**：Profile C 已加入 Alpha。  
**步骤**：

1. Profile C 打开 Alpha → 退出项目。
2. 确认退出。
3. 返回项目列表。

**预期**：

- 当前用户从工作区成员中移除。
- 本人项目角色席位释放。
- Alpha 从非管理员项目列表消失。
- 平台账号仍可登录。
- 历史审计保留退出记录。

#### ROLE-07 工作区负责人退出项目

**优先级**：P1  
**前置**：Profile B 是工作区负责人。  
**步骤**：退出 Alpha，确认警告文案。

**预期**：退出成功；提示项目可能没有工作区负责人；平台管理员仍可恢复管理。

#### ROLE-08 工作区类型和席位

**优先级**：P1  
**前置**：Profile A 已创建 `QA Type`，席位包含主持人、评审人、Builder。  
**步骤**：

1. Profile A 物化 `QA Type` 到 Alpha。
2. Profile B 认领主持人。
3. Profile C 认领评审人。
4. 释放并重新认领席位。

**预期**：席位、Leader、在任者和释放状态正确；重复认领幂等；非 admin 不能创建全局工作区类型。

### 5.3 项目设置与项目角色

#### PROJ-01 新建项目

**优先级**：P0

**优先级**：P0

**预期**：

- 详情即时刷新。
- 负责人必须是项目成员。
- 历史记录记录每个字段的前后值。

#### PROJ-03 项目详情展示

**优先级**：P1  
**步骤**：检查标题、状态、健康度、项目编号、Owner、日期、进度、工作区信息和事实卡。

**预期**：

- 工作区行显示相对路径、完整 ID 和复制图标。

**优先级**：P0

**优先级**：P0

**预期**：选择模版后才出现覆盖确认；角色按 code 合并/标记；无独立应用步骤。

**预期**：进行中任务标记「需改派」，保留原角色快照与原因；已完成任务不变。

#### PROJ-10 角色 revision 冲突

**优先级**：P1  
**步骤**：两个管理员分别编辑，后提交者确认。

**预期**：后提交者收到 revision 冲突提示；草稿保留；刷新后可重试。

#### PROJ-11 关闭未确认草稿

**优先级**：P1  
**步骤**：修改角色后关闭项目设置。

**预期**：弹出放弃确认；继续编辑保留草稿；放弃关闭丢弃草稿。

#### PROJ-12 模版定义和项目副本隔离

**优先级**：P0  
**步骤**：修改全局项目模版角色，检查 Alpha 与 Beta。

**预期**：既有项目角色副本不自动变化；新建或重新应用模版才使用新定义。

### 5.4 上下游核心链路

#### CHAIN-01 账号创建到项目任务

**优先级**：P0  
**步骤**：

1. Admin 创建 `qa-member`。
2. 将账号加入 Alpha，工作区角色 member，项目角色 Builder。
3. Profile C 登录。
4. 在任务管理创建 `QA-CHAIN-01` 并派发给 `qa-member`。
5. 在项目任务页签检查。

**预期**：账号、成员、项目角色和任务责任人一致；任务详情与项目统计同步。

#### CHAIN-02 角色派发到项目统计

**优先级**：P0  
**步骤**：创建 `QA-CHAIN-02`，接收人类型为角色 Builder。

**预期**：Builder 在任成员成为候选；任务出现在项目活跃任务；统计数量更新。

#### CHAIN-03 项目角色删除到任务改派

**优先级**：P0  
**前置**：存在进行中角色任务。  
**步骤**：删除对应项目角色并确认。

**预期**：任务标记需改派；项目任务页签显示原因；历史记录可追踪。

#### CHAIN-04 项目成员移除到工作流执行

**优先级**：P0  
**步骤**：启动使用 Builder 节点的工作流，然后移除 Builder 成员。

**预期**：旧实例保留角色快照；成员不能继续操作；新实例使用新成员角色。

#### CHAIN-05 角色改名不影响工作流

**优先级**：P0  
**步骤**：修改项目角色名称但保留 code/id，启动新实例。

**预期**：上下游匹配不变；旧实例显示快照名称；新实例显示新名称。

#### CHAIN-06 项目模版到工作流有效性

**优先级**：P0  
**步骤**：从模版应用工作流，再删除模版引用角色。

**预期**：角色下线被阻止；工作流模版有效性不被破坏。

#### CHAIN-07 AI Teammate 平台角色隔离

**优先级**：P0  
**步骤**：

1. 创建 Owner 为 `qa-owner` 的 AI Teammate。
2. 在项目成员下拉查看文案。
3. 将 AI 加入项目并设置项目角色。
4. 将 Owner 的全局平台角色改为 admin，再改回 member。

**预期**：显示 `名称·AI（by Owner名称）`；平台角色始终显示「未分配」，不随 Owner 平台角色变化；项目角色独立配置。

#### CHAIN-08 项目关注到工作台

**优先级**：P1  
**步骤**：关注 Alpha，打开工作台。

**预期**：重点关注出现 Alpha；取消关注后移除；跳转回 Alpha 详情。

#### CHAIN-09 项目日报到状态和上下游数据

**优先级**：P1  
**步骤**：更新 Alpha 日报。

**预期**：日报包含项目状态、活跃任务、阻塞工作流；重复生成覆盖当天快照并记录历史事件。

#### CHAIN-10 项目审计到问题定位

**优先级**：P0  
**步骤**：依次修改设置、角色、成员、模版和日报，再搜索历史。

**预期**：操作人、时间、对象、前后值完整；分类和关键词过滤准确；相同操作追加而非覆盖。

#### CHAIN-11 平台角色变更到项目显示

**优先级**：P0  
**步骤**：Admin 将 `qa-member` 全局角色从 member 改为 guest，再改回。

**预期**：项目成员表平台角色同步；工作区角色和项目角色不变；项目审计记录平台账号更新。

#### CHAIN-12 项目退出到下游访问

**优先级**：P0  
**步骤**：Profile C 退出 Alpha，再访问任务深链和工作流深链。

**预期**：Alpha 从非管理员列表消失；旧任务/工作流深链返回无权限；平台账号仍可访问 Beta。

### 5.5 安全、审计与异常

#### SEC-01 项目角色不能访问项目审计

**优先级**：P0  
**步骤**：给普通成员分配包含 `manage_roles` 的项目角色，再打开历史记录。

**预期**：历史记录页签不可见；直接调用历史接口返回 403；审计访问暂由平台/工作区管理口径控制。

#### SEC-02 项目内不能修改平台账号和全局角色

**优先级**：P0  
**步骤**：检查项目成员弹窗、项目设置和 API 调用。

**预期**：平台角色只读；不能改密码、启停用、全局角色；可改工作区成员角色和项目角色。

#### SEC-03 非成员不能查看项目详情

**优先级**：P0  
**步骤**：Profile E 直接访问 Alpha 详情 URL/接口。

**预期**：接口 403，GUI 不渲染成员、任务、工作流、日报和审计。

#### SEC-04 无效/过期 Token

**优先级**：P0  
**步骤**：篡改或清除 `pluginmax.collab.token` 后访问账号和项目页面。

**预期**：返回登录或明确未授权状态；不保留前一用户敏感数据。

#### SEC-05 跨项目角色复用隔离

**优先级**：P0  
**步骤**：从 Beta 复用角色并修改 Alpha 副本。

**预期**：Beta 和全局角色库不变；仅 Alpha 副本变化。

#### SEC-06 关闭入口不能绕过服务端

**优先级**：P0  
**步骤**：调用已下线的协作身份 HTTP 遗留接口，分别使用 admin、owner、member。

**预期**：管理接口保持原权限；项目服务调用不受影响；普通用户不能借遗留接口越权。

#### SEC-07 空数据与重复操作

**优先级**：P1  
**步骤**：无成员、无任务、无工作流、无历史、无日报时逐页检查；重复添加/移除/确认。

**预期**：显示明确空状态；重复操作幂等或给出业务错误；无空白页和未捕获异常。

#### SEC-08 浏览器兼容和窄屏

**优先级**：P1  
**步骤**：在桌面宽度和约 640px 宽度检查页面。

**预期**：按钮不溢出；文字不遮挡；角色/成员表格能合理换行；复制图标可点击。

## 6. 建议执行顺序

1. ACCT-01 至 ACCT-08。
2. ROLE-01 至 ROLE-08。
3. PROJ-01 至 PROJ-12。
4. CHAIN-01 至 CHAIN-12。

- 失败请求状态码和响应。
- 页面截图。
- 项目编号、工作区 ID、任务 ID、工作流实例 ID。
- 测试账号和浏览器 Profile 对照。

## 7. 缺陷等级

| 等级 | 判定                                                            |
| ---- | --------------------------------------------------------------- |
| P0   | 越权、数据丢失、角色失效、已启动工作流被破坏、项目无法进入      |
| P1   | 核心链路结果错误、审计缺失、账号/角色状态不一致、关键按钮不可用 |
| P2   | 数据正确但交互明显异常、筛选错误、布局影响阅读或操作            |
| P3   | 文案、间距、非关键样式问题                                      |

## 8. 通过标准

- 所有 P0 用例通过，P1 无阻塞缺陷。
- 平台账号、全局角色、工作区成员角色、项目角色之间职责清晰。
- 项目上下游任务与工作流链路一致。
- 项目历史记录可完整追溯操作人、时间、对象和字段变化。
- 非成员与无权限账号不能通过 GUI 或遗留 API 获取项目敏感数据。
- 控制台无未捕获 JavaScript 异常。
